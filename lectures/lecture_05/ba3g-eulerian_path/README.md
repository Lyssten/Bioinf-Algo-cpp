# Eulerian Path in a Directed Graph (BA3G)

## Задача

Найти эйлеров путь в ориентированном графе.

**Вход:** список смежности ориентированного графа
**Выход:** эйлеров путь в виде последовательности вершин

Формат входного файла Rosalind:
```text
0 -> 2
1 -> 3
2 -> 1
3 -> 0,4
6 -> 3,7
7 -> 8
8 -> 9
9 -> 6
```

**Пример:**
```
Вход:
0 -> 2
1 -> 3
2 -> 1
3 -> 0,4
6 -> 3,7
7 -> 8
8 -> 9
9 -> 6

Вывод: 6->7->8->9->6->3->0->2->1->3->4
```

## Теория

### Эйлеров путь vs эйлеров цикл

В задаче BA3F мы искали эйлеров **цикл** --- замкнутый маршрут, проходящий по каждому ребру ровно раз. Эйлеров **путь** --- то же самое, но начало и конец не обязаны совпадать. Условие существования отличается:

| | Эйлеров цикл | Эйлеров путь |
|---|---|---|
| **Степени вершин** | `in(v) = out(v)` для всех v | Ровно одна вершина с `out - in = 1` (старт), ровно одна с `in - out = 1` (финиш), остальные сбалансированы |
| **Начало/конец** | Любая вершина | Фиксированы дисбалансом степеней |

В примере: вершина 6 имеет `out = 2, in = 1` (out - in = 1) --- это старт. Вершина 4 имеет `out = 0, in = 1` (in - out = 1) --- это финиш. Все остальные вершины сбалансированы.

### Сведение к эйлерову циклу

Ключевая идея: вместо разработки отдельного алгоритма для эйлерова пути, мы **сводим** задачу к уже решённой задаче эйлерова цикла (BA3F). Как?

1. Находим startNode (`out - in = 1`) и endNode (`in - out = 1`)
2. Добавляем **временное ребро** `endNode -> startNode` --- теперь все вершины сбалансированы, граф стал эйлеровым
3. Находим эйлеров цикл (Хирхольцер, BA3F)
4. Находим в цикле временное ребро (переход `endNode -> startNode`) и «разрезаем» цикл в этом месте

После разрезания цикл превращается в путь, начинающийся в startNode и заканчивающийся в endNode. Временное ребро исчезает --- оно было «швом», по которому мы разрезали.

### Почему это работает?

Пусть эйлеров цикл после добавления временного ребра: `... -> endNode -> startNode -> ... -> endNode`. Если «разрезать» цикл на переходе `endNode -> startNode`, получим: `startNode -> ... -> endNode`. Это маршрут, проходящий по всем **исходным** рёбрам (временное ребро удалено), начинающийся в startNode и заканчивающийся в endNode --- то есть эйлеров путь.

### Особый случай: граф уже эйлеров

Если все вершины сбалансированы (нет `startNode` с `out - in = 1`), значит граф имеет эйлеров цикл, а не путь. Алгоритм корректно обрабатывает этот случай --- просто возвращает эйлеров цикл без добавления временного ребра.

## Применение

### В биологии

- **Сборка линейных геномов.** Кольцевые геномы (бактерии, плазмиды) собираются через эйлеров цикл (BA3F), но **линейные хромосомы** эукариот --- через эйлеров путь. Хромосома 1 человека (249 Мб) --- линейная молекула ДНК с теломерами на концах. При сборке граф де Брёйна из ридов хромосомы 1 имеет ровно два несбалансированных узла: один соответствует 5'-теломере (начало), другой --- 3'-теломере (конец). Ассемблер ищет эйлеров путь между ними.

- **Скаффолдинг контигов.** После первичной сборки ассемблер получает набор контигов (непрерывных фрагментов). Парные чтения (paired-end reads) позволяют определить порядок и ориентацию контигов. Задача скаффолдинга сводится к поиску эйлерова пути в графе контигов, где рёбра --- связи между контигами, определённые парными чтениями. Программа **SSPACE** (2011) использует именно этот подход для генома *Arabidopsis thaliana* (135 Мб, 5 хромосом).

- **Сборка транскриптома.** Программа **Trinity** (2011, Broad Institute) собирает транскриптом (все мРНК клетки) по RNA-seq данным. Каждый транскрипт --- линейная молекула, поэтому Trinity ищет набор эйлеровых путей в графе де Брёйна. Для транскриптома *Drosophila melanogaster* (~15 000 генов) Trinity восстанавливает ~30 000 транскриптов (с учётом альтернативного сплайсинга).

### В других областях

- **Задача китайского почтальона с фиксированным маршрутом.** Классическая задача --- обойти все улицы с минимальным повторением. Если граф улиц имеет ровно два нечётных узла (например, депо почтальона и конечная точка маршрута), решение --- эйлеров путь. Почтовые службы Японии оптимизируют маршруты доставки по ~3 500 районам, экономя ~15% пробега по сравнению с неоптимизированными маршрутами.

- **Тестирование печатных плат с точками входа/выхода.** Робот-тестер начинает на контакте питания (вход) и заканчивает на контакте заземления (выход). Соединения на плате --- рёбра. Оптимальный маршрут --- эйлеров путь от входа к выходу, проверяющий каждое соединение ровно раз. Для материнской платы с ~10 000 тестируемых соединений эйлеров путь находится за доли миллисекунды.

- **Планирование обхода сети дорог.** Снегоуборочная машина выезжает с базы, очищает все улицы и приезжает на другую базу (смена водителя). Если граф дорог имеет два несбалансированных узла (две базы), оптимальный маршрут --- эйлеров путь. Муниципальные службы Хельсинки оптимизируют маршруты ~200 снегоуборочных машин для ~6 000 км дорог.

## Алгоритм

### Идея

Алгоритм состоит из четырёх фаз:
1. **Анализ степеней** --- подсчитываем `in-degree` и `out-degree` для каждой вершины. Вершина с `out - in = 1` --- startNode, с `in - out = 1` --- endNode.
2. **Замыкание графа** --- добавляем временное ребро `endNode -> startNode`. Теперь все вершины сбалансированы.
3. **Эйлеров цикл** --- запускаем алгоритм Хирхольцера (BA3F) из startNode.
4. **Разрезание** --- находим в цикле переход `endNode -> startNode` (временное ребро) и «разрезаем» цикл: всё после разреза идёт в начало пути, всё до разреза --- в конец.

Пошаговый пример:
```
Граф: 0->2, 1->3, 2->1, 3->0, 3->4, 6->3, 6->7, 7->8, 8->9, 9->6

Шаг 1: startNode = 6 (out=2, in=1), endNode = 4 (out=0, in=1)
Шаг 2: добавляем ребро 4->6, граф замкнут
Шаг 3: эйлеров цикл из 6: 6->3->0->2->1->3->4->6->7->8->9->6
Шаг 4: находим переход 4->6, разрезаем:
        после разреза: 6->7->8->9->6->3->0->2->1->3->4
Результат: 6->7->8->9->6->3->0->2->1->3->4
```

### Псевдокод
```
EulerianPath(graph):
    // Фаза 1: анализ степеней
    для каждого ребра (v → u) в graph:
        outDeg[v] += 1
        inDeg[u] += 1

    startNode ← вершина с outDeg - inDeg = 1
    endNode   ← вершина с inDeg - outDeg = 1

    // Фаза 2: замыкание (если нужно)
    if startNode найден:
        graph[endNode].append(startNode)

    // Фаза 3: эйлеров цикл
    cycle ← EulerianCycle(graph, startNode)

    // Фаза 4: разрезание
    graph[endNode].removeLast()
    for i from 0 to |cycle| - 2:
        if cycle[i] = endNode и cycle[i+1] = startNode:
            path ← cycle[i+1..end] + cycle[1..i]
            return path

    return cycle
```

## Реализация на C++

```cpp
std::vector<int> eulerianCycle(std::map<int, std::vector<int>>& graph, int startNode) {
    std::map<int, size_t> edgeIndex;                                  // (1)
    for (auto& [node, _] : graph)
        edgeIndex[node] = 0;

    std::vector<int> stack = {startNode};                             // (2)
    std::vector<int> cycle;

    while (!stack.empty()) {
        int v = stack.back();
        if (edgeIndex.count(v) && edgeIndex[v] < graph[v].size()) {   // (3)
            int u = graph[v][edgeIndex[v]++];                         // (4)
            stack.push_back(u);
        } else {
            cycle.push_back(v);
            stack.pop_back();
        }
    }

    std::reverse(cycle.begin(), cycle.end());
    return cycle;
}

std::vector<int> eulerianPath(std::map<int, std::vector<int>>& graph) {
    std::map<int, int> inDeg, outDeg;                                 // (5)
    std::set<int> allNodes;

    for (auto& [v, neighbors] : graph) {                              // (6)
        allNodes.insert(v);
        outDeg[v] = static_cast<int>(neighbors.size());
        for (int u : neighbors) {
            inDeg[u]++;
            allNodes.insert(u);
        }
    }

    int startNode = -1, endNode = -1;                                 // (7)
    for (int v : allNodes) {
        int diff = outDeg[v] - inDeg[v];
        if (diff == 1) startNode = v;
        else if (diff == -1) endNode = v;
    }

    if (startNode == -1) {                                            // (8)
        return eulerianCycle(graph, graph.begin()->first);
    }

    graph[endNode].push_back(startNode);                              // (9)
    auto cycle = eulerianCycle(graph, startNode);                     // (10)
    graph[endNode].pop_back();                                        // (11)

    for (size_t i = 0; i + 1 < cycle.size(); ++i) {                  // (12)
        if (cycle[i] == endNode && cycle[i + 1] == startNode) {
            std::vector<int> path;
            for (size_t j = i + 1; j < cycle.size(); ++j)
                path.push_back(cycle[j]);
            for (size_t j = 1; j <= i; ++j)
                path.push_back(cycle[j]);
            return path;
        }
    }

    return cycle;                                                     // (13)
}
```

## Разбор кода

**1. `eulerianCycle` с параметром `startNode`**
```cpp
std::vector<int> eulerianCycle(std::map<int, std::vector<int>>& graph, int startNode) {
```
- Отличие от BA3F: функция принимает `startNode` как параметр, а не берёт `graph.begin()->first`.
- Для эйлерова пути критично начинать цикл именно из `startNode` (вершина с `out > in`), чтобы временное ребро `endNode -> startNode` гарантированно вошло в цикл.
- Граф передаётся по **мутабельной ссылке** (`&`), потому что мы временно добавляем ребро.

**2. Инициализация стека стартовой вершиной**
```cpp
std::vector<int> stack = {startNode};
```
- Initializer list (C++11): `{startNode}` создаёт вектор с одним элементом.
- Эквивалент: `std::vector<int> stack; stack.push_back(startNode);`, но компактнее.

**3. Двойная проверка: `edgeIndex.count(v)` + индекс**
```cpp
if (edgeIndex.count(v) && edgeIndex[v] < graph[v].size()) {
```
- `edgeIndex.count(v)` --- проверка, существует ли вершина в `edgeIndex`. Вершина endNode (до добавления временного ребра) может отсутствовать в `edgeIndex`, если у неё нет исходящих рёбер в исходном графе.
- Без `count(v)` обращение `edgeIndex[v]` создало бы запись с нулевым значением (особенность `map::operator[]`), а `graph[v]` создал бы пустой вектор --- это испортило бы граф.
- Ленивое вычисление `&&`: если `count(v) == 0`, второе условие не проверяется.

**4. Постфиксный инкремент в индексации**
```cpp
int u = graph[v][edgeIndex[v]++];
```
- `edgeIndex[v]++` --- постфиксный инкремент: сначала возвращает текущее значение (индекс ребра), потом увеличивает на 1.
- Объединяет два действия: (a) взять следующее непройденное ребро, (b) пометить его как пройденное.
- Эквивалент двух строк: `int u = graph[v][edgeIndex[v]]; edgeIndex[v]++;`, но идиоматичнее.

**5. Раздельный подсчёт `inDeg` и `outDeg`**
```cpp
std::map<int, int> inDeg, outDeg;
std::set<int> allNodes;
```
- Два отдельных словаря, а не один `balance = out - in`, потому что так яснее логика и проще отладка.
- `std::set<int> allNodes` --- собирает **все** вершины графа, включая «стоки» (вершины без исходящих рёбер). Вершина 4 в примере не является ключом `graph` (у неё нет исходящих рёбер), но она присутствует как цель ребра `3 -> 4`.
- Без `allNodes` мы бы не нашли endNode = 4, потому что итерация по ключам `graph` её пропустила бы.

**6. Подсчёт степеней: два прохода в одном цикле**
```cpp
for (auto& [v, neighbors] : graph) {
    allNodes.insert(v);
    outDeg[v] = static_cast<int>(neighbors.size());
    for (int u : neighbors) {
        inDeg[u]++;
        allNodes.insert(u);
    }
}
```
- `outDeg[v]` вычисляется напрямую из длины списка смежности: число исходящих рёбер = число соседей.
- `static_cast<int>(neighbors.size())` --- явное приведение `size_t` к `int`. Без каста компилятор выдаст предупреждение при последующем вычислении `outDeg[v] - inDeg[v]` (знаковая арифметика).
- `inDeg[u]++` --- для каждого ребра `v -> u` увеличиваем входящую степень `u`. `map::operator[]` создаёт запись с нулём при первом обращении --- удобно, не нужно инициализировать.

**7. Нахождение startNode и endNode**
```cpp
int startNode = -1, endNode = -1;
for (int v : allNodes) {
    int diff = outDeg[v] - inDeg[v];
    if (diff == 1) startNode = v;
    else if (diff == -1) endNode = v;
}
```
- Инициализация `-1` --- sentinel value (невозможный номер вершины).
- По теореме Эйлера, если эйлеров путь существует, будет **ровно одна** вершина с `diff = 1` и **ровно одна** с `diff = -1`.
- `outDeg[v] - inDeg[v]`: для вершин, отсутствующих в `outDeg` или `inDeg`, `map::operator[]` вернёт 0 (значение по умолчанию для `int`).

**8. Особый случай: граф уже эйлеров**
```cpp
if (startNode == -1) {
    return eulerianCycle(graph, graph.begin()->first);
}
```
- Если `startNode == -1`, все вершины сбалансированы --- граф имеет эйлеров цикл, а не путь.
- В этом случае не нужно добавлять временное ребро --- просто запускаем Хирхольцера.

**9. Добавление временного ребра**
```cpp
graph[endNode].push_back(startNode);
```
- `push_back` добавляет ребро `endNode -> startNode` в конец списка смежности endNode.
- Теперь `out(endNode)` увеличилась на 1, а `in(startNode)` --- тоже на 1 (неявно, при обходе). Все вершины стали сбалансированными.
- Ребро добавляется в **конец** вектора --- Хирхольцер пройдёт его последним из endNode (важно: это не влияет на корректность, но влияет на позицию разреза).

**10. Запуск Хирхольцера из startNode**
```cpp
auto cycle = eulerianCycle(graph, startNode);
```
- `auto` выводит тип `std::vector<int>`.
- Старт из startNode гарантирует, что временное ребро `endNode -> startNode` будет в цикле (цикл проходит через все рёбра).

**11. Удаление временного ребра**
```cpp
graph[endNode].pop_back();
```
- `pop_back()` --- O(1), удаляет последний элемент вектора. Именно временное ребро было последним (мы добавляли его через `push_back`).
- Это «уборка» --- восстанавливаем исходный граф. Без этого граф остался бы модифицированным после вызова функции (side effect).

**12. Разрезание цикла в месте временного ребра**
```cpp
for (size_t i = 0; i + 1 < cycle.size(); ++i) {
    if (cycle[i] == endNode && cycle[i + 1] == startNode) {
        std::vector<int> path;
        for (size_t j = i + 1; j < cycle.size(); ++j)
            path.push_back(cycle[j]);
        for (size_t j = 1; j <= i; ++j)
            path.push_back(cycle[j]);
        return path;
    }
}
```
- Ищем переход `endNode -> startNode` в цикле --- это место, где было временное ребро.
- `i + 1 < cycle.size()` --- безопасная граница: `size_t - 1` может переполниться, сложение безопасно.
- Первый цикл `j = i+1 .. end` --- берём всё **после** разреза (начиная с startNode).
- Второй цикл `j = 1 .. i` --- берём всё **до** разреза (заканчивая endNode). Индекс начинается с 1, потому что `cycle[0]` --- это `startNode`, который уже в начале path (из первого цикла, так как `cycle.back() == cycle[0]` в эйлеровом цикле).
- Результат: `startNode -> ... -> endNode` --- корректный эйлеров путь.

**13. Fallback: если временное ребро не найдено**
```cpp
return cycle;
```
- Защитный код: если по какой-то причине переход `endNode -> startNode` не найден в цикле, возвращаем цикл как есть.
- На корректных входных данных эта ветка никогда не выполняется.

## Анализ сложности

### Время: O(|E|)

**Обоснование.** Алгоритм сводится к одному вызову Хирхольцера (O(|E|)) плюс линейный препроцессинг:

1. **Подсчёт степеней:** один проход по всем рёбрам --- O(|E|).
2. **Поиск startNode/endNode:** один проход по всем вершинам --- O(|V|).
3. **Эйлеров цикл (Хирхольцер):** O(|E|) --- каждое ребро проходится ровно раз.
4. **Разрезание цикла:** один проход по cycle длины |E|+1 --- O(|E|).

**Узкое место в коде:**
```cpp
while (!stack.empty()) {                                    // суммарно O(|E|) итераций
    int v = stack.back();                                    // O(1)
    if (edgeIndex.count(v) && edgeIndex[v] < graph[v].size()) {
        int u = graph[v][edgeIndex[v]++];                    // O(1) — доступ по индексу
        stack.push_back(u);                                  // O(1) амортизированно
    } else {
        cycle.push_back(v);                                  // O(1) амортизированно
        stack.pop_back();                                    // O(1)
    }
}
```
Это ядро Хирхольцера --- тот же bottleneck, что и в BA3F. Все операции внутри цикла O(1), суммарное число итераций O(|E| + |V|). Фаза разрезания добавляет ещё O(|E|), но не меняет асимптотику.

Замечание: `edgeIndex.count(v)` --- поиск в `map` за O(log |V|). Формально это делает цикл O(|E| log |V|). С `unordered_map` было бы O(|E|) строго. На практике для графов сборки генома разница незаметна.

### Память: O(|V| + |E|)

**Обоснование.** Используются те же структуры, что в BA3F, плюс вспомогательные словари:

**Основные структуры данных:**
```cpp
std::map<int, std::vector<int>>& graph;   // O(|V| + |E|) — входной граф
std::map<int, size_t> edgeIndex;          // O(|V|) — индекс рёбер
std::vector<int> stack;                   // O(|E|) в худшем случае
std::vector<int> cycle;                   // O(|E| + 1) — результат
std::map<int, int> inDeg, outDeg;         // O(|V|) — степени вершин
std::set<int> allNodes;                   // O(|V|) — множество вершин
std::vector<int> path;                    // O(|E|) — итоговый путь
```
- `inDeg`, `outDeg`, `allNodes` --- дополнительные O(|V|) по сравнению с BA3F.
- `path` --- копия cycle (минус одна вершина), O(|E|).
- Итого: O(|V| + |E|) --- доминирует размер графа и результата.
