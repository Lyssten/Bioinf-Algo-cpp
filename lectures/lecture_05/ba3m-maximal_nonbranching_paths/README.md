# Maximal Non-Branching Paths (BA3M)

## Задача

Найти все максимальные неветвящиеся пути в ориентированном графе.

**Вход:** список смежности ориентированного графа (вершины — целые числа)
**Выход:** все максимальные неветвящиеся пути (включая изолированные циклы)

Формат входного файла Rosalind:
```text
1 -> 2
2 -> 3
3 -> 4,5
6 -> 7
7 -> 6
```

**Пример:**
```
Вход:
1 -> 2
2 -> 3
3 -> 4,5
6 -> 7
7 -> 6

Вывод:
1 -> 2 -> 3
3 -> 4
3 -> 5
7 -> 6 -> 7
```

Вершина 2 имеет in-degree = 1 и out-degree = 1, поэтому она «поглощается» в путь 1 -> 2 -> 3. Вершина 3 имеет out-degree = 2 (ветвление), поэтому она начинает два новых пути: 3 -> 4 и 3 -> 5. Вершины 6 и 7 обе имеют in-degree = out-degree = 1 и не достижимы из фазы 1 — это изолированный цикл 7 -> 6 -> 7.

## Теория

### Определения

**1-in-1-out вершина** — вершина v, у которой in-degree(v) = out-degree(v) = 1. Такая вершина не создаёт ветвления: в неё входит ровно одно ребро и выходит ровно одно. Она лишь «транзитно» передаёт путь дальше.

**Неветвящийся путь** (non-branching path) — путь v₁ -> v₂ -> ... -> vₖ, в котором все **внутренние** вершины (v₂, ..., vₖ₋₁) являются 1-in-1-out. Начальная и конечная вершины могут иметь произвольные степени.

**Максимальный неветвящийся путь** — неветвящийся путь, который нельзя продлить ни влево, ни вправо, сохраняя свойство неветвления внутренних вершин.

**Изолированный цикл** — цикл, в котором **все** вершины являются 1-in-1-out. Такой цикл не имеет ни одной вершины с «нетривиальным» ветвлением, поэтому ни одна вершина не будет стартовой в фазе 1 алгоритма. Без специальной обработки эти циклы были бы пропущены.

### Зачем это нужно

В графе де Брёйна, построенном из геномных ридов, каждый максимальный неветвящийся путь соответствует **контигу** — максимальному фрагменту генома, который можно однозначно реконструировать. Точки ветвления в графе соответствуют **повторам** или **ошибкам** в данных секвенирования. Между двумя точками ветвления последовательность однозначна — это и есть контиг.

Эйлеров путь (BA3F) даёт полную реконструкцию генома только в идеальном случае (без повторов, без ошибок, полное покрытие). На практике граф де Брёйна не имеет единственного эйлерова пути, и ассемблер вместо этого извлекает максимальные неветвящиеся пути — контиги.

### Связь с эйлеровым путём

Задачи BA3F (эйлеров цикл) и BA3M (максимальные неветвящиеся пути) решают **противоположные** крайности:

| Свойство | BA3F | BA3M |
|---|---|---|
| **Граф** | идеальный (эйлеров) | произвольный |
| **Результат** | один путь через все рёбра | набор фрагментов (контигов) |
| **Предположение** | нет повторов/ошибок | повторы и ошибки — норма |
| **Практическое применение** | кольцевые геномы без повторов | реальная сборка из ридов |

В конвейере реального ассемблера BA3M — следующий шаг после построения графа де Брёйна (BA3E), когда эйлеров путь (BA3F) невозможен.

## Применение

### В биологии

- **Сборка контигов — ключевой шаг ассемблеров.** Программы SPAdes, Velvet, MEGAHIT, SOAPdenovo строят граф де Брёйна из ридов секвенатора, а затем извлекают максимальные неветвящиеся пути — контиги. Для генома *E. coli* (4.6 Мб) SPAdes обычно генерирует ~100-200 контигов (N50 ~100-300 Кб), каждый из которых — один максимальный неветвящийся путь. Для генома человека (3.2 Гб) контигов может быть ~20 000-50 000.

- **Упрощение графа де Брёйна.** После извлечения неветвящихся путей граф «сжимается»: цепочка из тысяч 1-in-1-out узлов заменяется одним ребром (контигом). Граф *E. coli* при k=55 содержит ~8 млн узлов; после сжатия остаётся ~500 «суперузлов». Это делает граф обозримым для последующих этапов (scaffolding, gap filling).

- **Метагеномная сборка.** MEGAHIT (Li et al., 2015) при сборке метагеномов окружающей среды (сотни видов одновременно) строит граф де Брёйна, извлекает контиги как неветвящиеся пути, а затем кластеризует их по видам. Для образца почвы с ~1000 видов генерируется ~10⁶ контигов.

- **Circularization.** Изолированные циклы (фаза 2 алгоритма) соответствуют кольцевым молекулам: плазмидам, митохондриальной ДНК, геномам бактериофагов. Unicycler (Wick et al., 2017) целенаправленно ищет такие циклы для сборки кольцевых геномов бактерий.

### В других областях

- **Упрощение дорожных сетей.** В картографических сервисах (Google Maps, OSM) цепочки перекрёстков, соединённых единственной дорогой без развилок, сжимаются в одно ребро графа. Дорожная сеть Москвы содержит ~500 000 перекрёстков, но после сжатия неветвящихся путей остаётся ~50 000 узлов. Это ускоряет алгоритмы маршрутизации (Dijkstra, A*) на порядок.

- **Упрощение речных сетей в ГИС.** В гидрологическом моделировании речные сети представляются как ориентированные графы (от истока к устью). Максимальные неветвящиеся пути соответствуют участкам реки между слияниями (confluences). Речная сеть Амазонки (~1100 притоков) сжимается до ~300 узлов-слияний.

- **Минимизация цифровых схем.** В электронном проектировании (EDA) цепочки логических элементов без ветвлений (fan-out = 1, fan-in = 1) объединяются в один блок при оптимизации netlist. Для процессора с ~10⁹ транзисторов это сокращает граф на 30-50%, ускоряя timing analysis.

- **Анализ потока управления в компиляторах.** Компиляторы (LLVM, GCC) строят CFG (Control Flow Graph) программы и объединяют последовательные базовые блоки без ветвлений в один блок — это в точности поиск максимальных неветвящихся путей. Оптимизация «block merging» в LLVM применяется к каждой компилируемой функции.

## Алгоритм

### Идея

Алгоритм состоит из двух фаз, основанных на ключевом наблюдении: максимальный неветвящийся путь может начинаться **только** из вершины, которая **не** является 1-in-1-out (т.е. из вершины с нетривиальным ветвлением). Исключение — изолированные циклы, где все вершины 1-in-1-out.

**Фаза 1.** Для каждой не-1-in-1-out вершины v с outDeg(v) > 0: для каждого исходящего ребра v -> w запускаем «прокатку» вдоль цепочки 1-in-1-out вершин, пока не упрёмся в вершину с нетривиальной степенью. Все посещённые вершины помечаем.

**Фаза 2.** Обходим оставшиеся непомеченные 1-in-1-out вершины. Каждая такая вершина — часть изолированного цикла. Запускаем обход по циклу до возврата в начальную вершину.

**Почему это корректно?** Каждое ребро графа принадлежит ровно одному максимальному неветвящемуся пути. Ребро из не-1-in-1-out вершины обязательно начинает новый путь (фаза 1). Рёбра между 1-in-1-out вершинами, не затронутые фазой 1, образуют изолированные циклы (фаза 2).

### Псевдокод
```
MaximalNonBranchingPaths(graph):
    вычислить inDeg[v] и outDeg[v] для каждой вершины v
    paths ← []
    visited ← {}

    // Фаза 1: пути из не-1-in-1-out вершин
    for каждая вершина v в графе:
        if v не является 1-in-1-out и outDeg[v] > 0:
            for каждое ребро v → w:
                path ← [v, w]
                visited ← visited ∪ {v, w}
                while w является 1-in-1-out:
                    w ← единственный сосед w
                    path.append(w)
                    visited ← visited ∪ {w}
                paths.append(path)

    // Фаза 2: изолированные циклы
    for каждая вершина v в графе:
        if v является 1-in-1-out и v ∉ visited:
            cycle ← [v]
            visited ← visited ∪ {v}
            w ← сосед v
            while w ≠ v:
                cycle.append(w)
                visited ← visited ∪ {w}
                w ← сосед w
            cycle.append(v)          // замкнуть цикл
            paths.append(cycle)

    return paths
```

## Реализация на C++

```cpp
std::vector<std::vector<int>> maximalNonBranchingPaths(
        const std::map<int, std::vector<int>>& graph) {

    std::map<int, int> inDeg, outDeg;                              // (1)
    std::set<int> allNodes;

    for (auto& [v, neighbors] : graph) {                           // (2)
        allNodes.insert(v);
        outDeg[v] = static_cast<int>(neighbors.size());
        for (int u : neighbors) {
            inDeg[u]++;
            allNodes.insert(u);
        }
    }

    for (int v : allNodes) {                                       // (3)
        if (!inDeg.count(v)) inDeg[v] = 0;
        if (!outDeg.count(v)) outDeg[v] = 0;
    }

    auto is1in1out = [&](int v) {                                  // (4)
        return inDeg[v] == 1 && outDeg[v] == 1;
    };

    std::vector<std::vector<int>> paths;
    std::set<int> visited;                                         // (5)

    // Phase 1: paths starting from non-1-in-1-out nodes
    for (int v : allNodes) {                                       // (6)
        if (!is1in1out(v) && outDeg[v] > 0) {
            auto it = graph.find(v);
            if (it == graph.end()) continue;

            for (int w : it->second) {                             // (7)
                std::vector<int> path = {v, w};
                visited.insert(v);
                visited.insert(w);

                while (is1in1out(w)) {                             // (8)
                    auto wIt = graph.find(w);
                    if (wIt == graph.end() || wIt->second.empty()) break;
                    w = wIt->second[0];
                    path.push_back(w);
                    visited.insert(w);
                }

                paths.push_back(path);
            }
        }
    }

    // Phase 2: isolated cycles
    for (int v : allNodes) {                                       // (9)
        if (is1in1out(v) && !visited.count(v)) {
            auto it = graph.find(v);
            if (it == graph.end()) continue;

            std::vector<int> cycle = {v};                          // (10)
            visited.insert(v);
            int w = it->second[0];

            while (w != v) {                                       // (11)
                cycle.push_back(w);
                visited.insert(w);
                auto wIt = graph.find(w);
                if (wIt == graph.end()) break;
                w = wIt->second[0];
            }

            cycle.push_back(v);                                    // (12)
            paths.push_back(cycle);
        }
    }

    return paths;
}
```

## Разбор кода

**1. Структуры для хранения степеней**
```cpp
std::map<int, int> inDeg, outDeg;
std::set<int> allNodes;
```
- `inDeg` и `outDeg` — входящая и исходящая степени каждой вершины. Тип `std::map<int, int>`: ключ — номер вершины, значение — степень.
- `allNodes` — множество всех вершин графа (включая те, которые встречаются только как целевые вершины рёбер и не имеют собственных записей в `graph`). `std::set<int>` гарантирует уникальность и упорядоченность — обход в фазах 1 и 2 идёт по возрастанию номеров вершин.
- Отдельный `allNodes` необходим, потому что `graph` — это `std::map<int, std::vector<int>>`, где ключи — только вершины-источники. Вершина 4 из примера (только целевая, без исходящих рёбер) отсутствует как ключ в `graph`, но присутствует в `allNodes`.

**2. Вычисление степеней — structured bindings**
```cpp
for (auto& [v, neighbors] : graph) {
    allNodes.insert(v);
    outDeg[v] = static_cast<int>(neighbors.size());
    for (int u : neighbors) {
        inDeg[u]++;
        allNodes.insert(u);
    }
}
```
- `auto& [v, neighbors]` — structured binding (C++17): `v` привязывается к ключу (`int`), `neighbors` — к значению (`std::vector<int>`). Знак `&` означает привязку по ссылке (без копирования).
- `static_cast<int>(neighbors.size())` — явное приведение `size_t` (тип возвращаемого `size()`) к `int`. Необходимо, потому что `outDeg` хранит `int`. Без каста компилятор выдаст предупреждение о сужающем преобразовании.
- `inDeg[u]++` — оператор `[]` в `std::map` при обращении к несуществующему ключу создаёт запись с нулевым значением (value-initialization для `int` = 0), а затем `++` инкрементирует до 1. Это идиоматический способ подсчёта частот в C++.

**3. Инициализация нулевых степеней**
```cpp
for (int v : allNodes) {
    if (!inDeg.count(v)) inDeg[v] = 0;
    if (!outDeg.count(v)) outDeg[v] = 0;
}
```
- Вершины, не встречающиеся как источники (outDeg) или как цели (inDeg) рёбер, не получили записей на предыдущем шаге. Например, вершина 4 из примера: `outDeg[4]` не был установлен, потому что у вершины 4 нет исходящих рёбер.
- `count(v)` возвращает 0 или 1 — есть ли ключ v в map. Альтернатива — `find(v) != end()`, но `count` короче.
- Без этого шага вызов `is1in1out(4)` обратился бы к `outDeg[4]`, что создало бы запись с 0 (value-initialization), но полагаться на этот побочный эффект `operator[]` — плохая практика. Явная инициализация делает намерение очевидным.

**4. Лямбда `is1in1out` с захватом по ссылке**
```cpp
auto is1in1out = [&](int v) {
    return inDeg[v] == 1 && outDeg[v] == 1;
};
```
- `[&]` — захватывает все переменные из окружающего scope по ссылке. В данном случае это `inDeg` и `outDeg`. Захват по ссылке (а не по значению `[=]`) важен: лямбда читает **текущее состояние** map, а не копию.
- `auto` выводит тип лямбды (каждая лямбда имеет уникальный анонимный тип, который нельзя записать явно).
- Лямбда используется как предикат: вызывается `is1in1out(v)` — синтаксически как обычная функция, но с доступом к контексту.
- Альтернатива — обычная функция с двумя дополнительными параметрами, но лямбда лаконичнее и локальнее.

**5. `std::set<int> visited` — отслеживание посещённых вершин**
```cpp
std::set<int> visited;
```
- `visited` — множество вершин, уже назначенных какому-либо пути. Используется в фазе 2 для определения, является ли 1-in-1-out вершина частью изолированного цикла (непосещённая) или уже включена в путь из фазы 1.
- `std::set` выбран вместо `std::unordered_set`, потому что для данной задачи разница в производительности несущественна (O(log n) vs O(1) на операцию), а `set` детерминирован.
- `visited.count(v)` возвращает 0 или 1 — O(log n) для `std::set`.

**6. Фаза 1 — поиск путей из не-1-in-1-out вершин**
```cpp
for (int v : allNodes) {
    if (!is1in1out(v) && outDeg[v] > 0) {
        auto it = graph.find(v);
        if (it == graph.end()) continue;
```
- Два условия: вершина не является 1-in-1-out (это потенциальное начало пути) **и** имеет исходящие рёбра (иначе из неё ничего не начинается).
- `graph.find(v)` вместо `graph[v]` — потому что `graph` передан как `const`, а `operator[]` не-const (он может создать запись). `find` возвращает итератор, не модифицируя map.
- `it == graph.end()` — проверка на случай, если вершина присутствует только как целевая (нет записи в `graph`). Это защитное программирование: условие `outDeg[v] > 0` уже должно отсечь такие вершины, но проверка `find` делает код надёжнее.

**7. Перебор исходящих рёбер — начало каждого пути**
```cpp
for (int w : it->second) {
    std::vector<int> path = {v, w};
    visited.insert(v);
    visited.insert(w);
```
- `it->second` — список соседей вершины v (тип `std::vector<int>`). `it->first` — сама вершина v.
- Для **каждого** исходящего ребра из v создаётся отдельный путь. Если outDeg(v) = 3, будут созданы три пути, все начинающиеся с v.
- `std::vector<int> path = {v, w}` — инициализация вектора списком (initializer list, C++11). Путь начинается с двух вершин: начальной v и её соседа w.
- `visited.insert(v)` вызывается многократно для одной и той же вершины v (по разу на каждое исходящее ребро), но `set::insert` для дубликатов — O(log n) без побочных эффектов.

**8. «Прокатка» по цепочке 1-in-1-out вершин**
```cpp
while (is1in1out(w)) {
    auto wIt = graph.find(w);
    if (wIt == graph.end() || wIt->second.empty()) break;
    w = wIt->second[0];
    path.push_back(w);
    visited.insert(w);
}
```
- Цикл продолжается, пока текущая вершина w является 1-in-1-out. Как только w перестаёт быть 1-in-1-out (ветвление, тупик, или вершина с множественным входом), путь завершается.
- `wIt->second[0]` — единственный сосед вершины w (outDeg = 1, поэтому вектор содержит ровно один элемент). Индекс `[0]` безопасен: мы знаем, что outDeg(w) = 1.
- Переменная `w` **переиспользуется** (reassigned) на каждой итерации — это идиома «бегущий указатель» (runner pointer).
- Защитная проверка `wIt == graph.end() || wIt->second.empty()` — на случай повреждённых данных (вершина заявлена с outDeg=1, но не имеет записи в графе).

**9. Фаза 2 — поиск изолированных циклов**
```cpp
for (int v : allNodes) {
    if (is1in1out(v) && !visited.count(v)) {
```
- Вершина должна быть 1-in-1-out **и** не посещена в фазе 1. Обе проверки необходимы:
  - 1-in-1-out — только такие вершины могут быть частью изолированного цикла
  - не посещена — если посещена, значит уже включена в путь из фазы 1

**10. Начало цикла**
```cpp
std::vector<int> cycle = {v};
visited.insert(v);
int w = it->second[0];
```
- Цикл начинается с произвольной непосещённой 1-in-1-out вершины v. Выбор не влияет на корректность — цикл будет содержать все те же вершины, просто начнётся с другой точки.
- `it->second[0]` — единственный сосед (outDeg = 1).

**11. Обход цикла**
```cpp
while (w != v) {
    cycle.push_back(w);
    visited.insert(w);
    auto wIt = graph.find(w);
    if (wIt == graph.end()) break;
    w = wIt->second[0];
}
```
- Идём по единственным исходящим рёбрам, пока не вернёмся в начальную вершину v. Это гарантировано произойдёт, потому что все вершины 1-in-1-out, и цикл конечен.
- Условие `wIt == graph.end()` — защитная проверка, которая в корректном графе никогда не сработает.

**12. Замыкание цикла**
```cpp
cycle.push_back(v);
paths.push_back(cycle);
```
- Начальная вершина v добавляется в конец, замыкая цикл: `[7, 6, 7]` означает цикл 7 -> 6 -> 7.
- Формат совпадает с форматом Rosalind: первая и последняя вершина цикла одинаковы.

## Анализ сложности

### Время: O(|V| + |E|)

**Обоснование.** Каждое ребро графа обрабатывается ровно один раз: либо в фазе 1 (при «прокатке» по цепочке 1-in-1-out вершин), либо в фазе 2 (при обходе изолированного цикла). Каждая вершина обрабатывается конечное число раз (проверка степеней, проверка `visited`).

**Узкое место — вычисление степеней (O(|V| + |E|)):**
```cpp
for (auto& [v, neighbors] : graph) {              // O(|V|) итераций по вершинам
    allNodes.insert(v);                             // O(log|V|) — вставка в set
    outDeg[v] = static_cast<int>(neighbors.size()); // O(1)
    for (int u : neighbors) {                       // суммарно O(|E|) по всем вершинам
        inDeg[u]++;                                 // O(log|V|) — доступ к map
        allNodes.insert(u);                         // O(log|V|)
    }
}
```
Суммарно: O(|E| * log|V|). Это доминирующая часть из-за `std::map` и `std::set`.

**Узкое место — фаза 1 (O(|E| * log|V|)):**
```cpp
for (int v : allNodes) {                           // O(|V|) итераций
    if (!is1in1out(v) && outDeg[v] > 0) {
        for (int w : it->second) {                 // суммарно O(|E|) рёбер
            while (is1in1out(w)) {                 // каждое ребро — макс. 1 раз
                w = wIt->second[0];                // O(1)
                visited.insert(w);                 // O(log|V|)
            }
        }
    }
}
```
Внутренний `while` суммарно по всем вершинам проходит каждое ребро не более одного раза. Операции с `set` (`visited.insert`, `visited.count`) — O(log|V|) каждая.

**Итого:** O((|V| + |E|) * log|V|). С `std::unordered_map` и `std::unordered_set` было бы O(|V| + |E|) в среднем.

### Память: O(|V| + |E|)

**Обоснование:**
```cpp
std::map<int, std::vector<int>> graph;    // O(|V| + |E|) — входной граф
std::map<int, int> inDeg, outDeg;         // O(|V|) — по записи на вершину
std::set<int> allNodes;                   // O(|V|) — множество всех вершин
std::set<int> visited;                    // O(|V|) — множество посещённых вершин
std::vector<std::vector<int>> paths;      // O(|V| + |E|) — все пути суммарно
```
- `paths` суммарно содержит каждую вершину не более нескольких раз (стартовая вершина может повторяться в нескольких путях, но каждое ребро — ровно в одном пути). Суммарный размер всех путей = O(|V| + |E|).
- `inDeg`, `outDeg`, `allNodes`, `visited` — по O(|V|) каждый.
- Итого: O(|V| + |E|).
