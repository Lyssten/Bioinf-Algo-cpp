# Generate Contigs from a Collection of Reads (BA3K)

## Задача

Сгенерировать все контиги из коллекции ридов (k-меров).

**Вход:** коллекция k-меров Patterns
**Выход:** все контиги --- строки, соответствующие максимальным неветвящимся путям в графе де Брёйна

Формат входного файла Rosalind:
```text
kmer1
kmer2
...
```

**Пример:**
```
Вход:
ATG
ATG
TGT
TGG
CAT
GGA
GAT
AGA

Вывод: AGA ATG ATG CAT GAT TGGA TGT
```

## Теория

### Почему контиги, а не полный геном?

В идеальном мире граф де Брёйна имеет единственный эйлеров путь --- и мы реконструируем полный геном (BA3B). В реальности:

1. **Повторы** создают вершины с in-degree > 1 или out-degree > 1 (точки ветвления). В этих точках мы не знаем, по какому ребру идти дальше.
2. **Ошибки секвенирования** создают «тупиковые» ответвления (рёбра, ведущие в узлы без исходящих рёбер).
3. **Неполное покрытие** создаёт разрывы в графе (пропущенные рёбра).

Между точками ветвления путь однозначен. Каждый такой однозначный фрагмент --- **контиг** (contiguous sequence).

### Неветвящиеся пути

Узел v в ориентированном графе называется **1-in-1-out**, если in-degree(v) = out-degree(v) = 1. Это «проходной» узел: войти можно только одним способом, выйти --- тоже одним.

**Максимальный неветвящийся путь** (maximal non-branching path) --- путь, в котором:
- Все внутренние узлы (кроме первого и последнего) --- 1-in-1-out
- Путь нельзя расширить: первый узел --- **не** 1-in-1-out (точка ветвления или источник), последний --- тоже

Пример на графе:
```
              A ──→ B ──→ C ──→ D
              ↑                  ↓
              H ←── G ←── F ←── E
                          ↑
                    I ────┘
```
Если F имеет in-degree = 2 (из E и из I), то F --- не 1-in-1-out. Максимальные неветвящиеся пути:
- A -> B -> C -> D -> E -> F (F не 1-in-1-out --- стоп)
- F -> G -> H -> A (A не 1-in-1-out --- стоп)
- I -> F (F не 1-in-1-out --- стоп)

### Изолированные циклы

Особый случай: если все узлы в компоненте связности --- 1-in-1-out, то компонента --- **изолированный цикл**. Такой цикл не присоединён к точкам ветвления и не будет найден фазой 1 алгоритма (та стартует только из не-1-in-1-out узлов). Поэтому нужна отдельная фаза 2 для обнаружения изолированных циклов.

### Связь контигов со строками

Каждый максимальный неветвящийся путь в графе де Брёйна --- последовательность узлов ((k-1)-меров). «Произнесение» (spelling) пути: берём первый узел целиком, затем от каждого следующего узла --- последний символ. Результат --- строка (контиг), соответствующая k-мерам на рёбрах пути.

## Применение

### В биологии

- **Выход реального ассемблера.** Ни один ассемблер не выдаёт одну последовательность от первого до последнего нуклеотида хромосомы. Результат --- набор контигов. Для генома *E. coli* (4.6 Мб) ассемблер SPAdes при покрытии 50x и k=55 генерирует 100--200 контигов суммарной длиной ~4.6 Мб. Для генома человека (3.2 Гб) --- десятки тысяч контигов.

- **Метрика N50.** Качество сборки измеряется метрикой **N50**: контиги сортируются по длине, и N50 --- длина контига, при которой суммарная длина более длинных контигов составляет 50% генома. Для хорошей сборки *E. coli* N50 > 100 Кб. Программа **QUAST** (Quality Assessment Tool for Genome Assemblies, 2013) вычисляет N50 и десятки других метрик, сравнивая контиги с референсным геномом.

- **Контиги как входные данные для скаффолдинга.** Контиги --- промежуточный результат. Следующий шаг --- **скаффолдинг**: парные чтения (BA3J) соединяют контиги в скаффолды (контиги + промежутки известной длины). Программа **SSPACE** (2011) использует mate-pair данные: если два конца одной пары попадают в разные контиги, контиги объединяются. Для *Staphylococcus aureus* (2.8 Мб) SSPACE сокращает 120 контигов до 10 скаффолдов.

- **Метагеномная сборка.** При секвенировании микробиома (смеси ДНК сотен видов) контиги --- единственный адекватный формат вывода: полные геномы невозможно реконструировать из смешанных данных. **MEGAHIT** (2015) генерирует контиги из метагеномных данных и группирует их по организмам (binning). Для образца кишечного микробиома (~500 видов) MEGAHIT генерирует ~300 000 контигов.

### В других областях

- **Сегментация дорожных сетей.** Максимальные неветвящиеся пути в графе дорог --- это участки без перекрёстков (прямые дороги между развязками). В транспортном планировании такие сегменты используются как базовые единицы для расчёта трафика. Для дорожной сети Москвы (~200 000 рёбер) алгоритм выделяет ~50 000 сегментов.

- **Анализ речных сетей.** В гидрологии речная сеть моделируется как ориентированный граф (направление --- вниз по течению). Максимальные неветвящиеся пути --- это участки реки между слияниями или разветвлениями. Классификация Стралера (Strahler number) присваивает порядок каждому сегменту: ручей без притоков --- порядок 1, слияние двух ручьёв одного порядка n даёт порядок n+1. Для Амазонки порядок = 12.

## Алгоритм

### Идея

Алгоритм работает в две фазы:

**Фаза 1:** Для каждой вершины v, которая **не** является 1-in-1-out и имеет хотя бы одно исходящее ребро --- инициируем путь из v. Идём по 1-in-1-out узлам, пока не встретим не-1-in-1-out узел. Каждый путь --- один контиг.

**Фаза 2:** Обходим оставшиеся (непосещённые) 1-in-1-out узлы --- они образуют изолированные циклы. Из каждого такого узла стартуем обход цикла.

Почему фаза 1 стартует из не-1-in-1-out узлов: такие узлы --- «границы» контигов (точки ветвления, источники, стоки). Любой максимальный неветвящийся путь **начинается и заканчивается** в не-1-in-1-out узлах (или образует изолированный цикл). Стартуя из каждого такого узла по каждому исходящему ребру, мы гарантированно находим все контиги.

### Псевдокод
```
GenerateContigs(kmers):
    graph ← DeBruijnGraph(kmers)              // BA3E

    Вычислить in-degree и out-degree каждого узла
    is1in1out(v) ← (in[v] = 1 AND out[v] = 1)

    contigs ← []
    visited ← {}

    // Фаза 1: пути из точек ветвления
    for each v in allNodes:
        if NOT is1in1out(v) AND out[v] > 0:
            for each w in graph[v]:
                path ← [v, w]
                visited += {v, w}
                current ← w
                while is1in1out(current):
                    current ← graph[current][0]
                    path.append(current)
                    visited += {current}
                contigs.append(spellPath(path))

    // Фаза 2: изолированные циклы
    for each v in allNodes:
        if is1in1out(v) AND v ∉ visited:
            cycle ← [v]
            visited += {v}
            current ← graph[v][0]
            while current ≠ v:
                cycle.append(current)
                visited += {current}
                current ← graph[current][0]
            cycle.append(v)
            contigs.append(spellPath(cycle))

    return contigs
```

## Реализация на C++

```cpp
std::string spellPath(const std::vector<std::string>& path) {
    if (path.empty()) return "";                                         // (1)
    std::string result = path[0];
    for (size_t i = 1; i < path.size(); ++i)
        result += path[i].back();
    return result;
}

std::vector<std::string> generateContigs(const std::vector<std::string>& kmers) {
    auto graph = buildDeBruijn(kmers);                                   // (2)

    std::map<std::string, int> inDeg, outDeg;                            // (3)
    std::set<std::string> allNodes;

    for (auto& [v, neighbors] : graph) {
        allNodes.insert(v);
        outDeg[v] = static_cast<int>(neighbors.size());
        for (auto& u : neighbors) {
            inDeg[u]++;
            allNodes.insert(u);
        }
    }

    for (auto& v : allNodes) {                                           // (4)
        if (!inDeg.count(v)) inDeg[v] = 0;
        if (!outDeg.count(v)) outDeg[v] = 0;
    }

    auto is1in1out = [&](const std::string& v) {                         // (5)
        return inDeg[v] == 1 && outDeg[v] == 1;
    };

    std::vector<std::string> contigs;
    std::set<std::string> visited;

    // Фаза 1: пути из точек ветвления
    for (auto& v : allNodes) {                                           // (6)
        if (!is1in1out(v) && outDeg[v] > 0) {
            auto it = graph.find(v);
            if (it == graph.end()) continue;

            for (auto& w : it->second) {                                 // (7)
                std::vector<std::string> path = {v, w};
                visited.insert(v);
                visited.insert(w);

                std::string current = w;
                while (is1in1out(current)) {                             // (8)
                    auto cIt = graph.find(current);
                    if (cIt == graph.end() || cIt->second.empty()) break;
                    current = cIt->second[0];
                    path.push_back(current);
                    visited.insert(current);
                }

                contigs.push_back(spellPath(path));                      // (9)
            }
        }
    }

    // Фаза 2: изолированные циклы
    for (auto& v : allNodes) {                                           // (10)
        if (is1in1out(v) && !visited.count(v)) {
            auto it = graph.find(v);
            if (it == graph.end()) continue;

            std::vector<std::string> cycle = {v};
            visited.insert(v);
            std::string current = it->second[0];

            while (current != v) {                                       // (11)
                cycle.push_back(current);
                visited.insert(current);
                auto cIt = graph.find(current);
                if (cIt == graph.end()) break;
                current = cIt->second[0];
            }

            cycle.push_back(v);                                          // (12)
            contigs.push_back(spellPath(cycle));
        }
    }

    return contigs;
}
```

## Разбор кода

**1. Функция `spellPath` --- сборка строки из пути**
```cpp
std::string result = path[0];
for (size_t i = 1; i < path.size(); ++i)
    result += path[i].back();
```
- Первый узел копируется целиком: `result = "AT"`.
- От каждого следующего берётся только последний символ: `back()` --- O(1) доступ к последнему элементу строки.
- `result += char` --- amortized O(1) (добавление одного символа в конец строки).
- Для пути `["AT", "TG", "GT"]` результат: `"AT" + "G" + "T" = "ATGT"`.

**2. Построение графа де Брёйна**
```cpp
auto graph = buildDeBruijn(kmers);
```
- `buildDeBruijn` из BA3E: каждый k-мер -> ребро из prefix в suffix.
- `auto` выводит тип как `Graph = std::map<std::string, std::vector<std::string>>`.
- Дублирующиеся k-меры (два `ATG` в примере) создают два ребра из `AT` в `TG` --- мультиграф.

**3. Подсчёт степеней**
```cpp
std::map<std::string, int> inDeg, outDeg;
std::set<std::string> allNodes;
```
- `outDeg[v]` = число рёбер, исходящих из v = `graph[v].size()`.
- `inDeg[u]` считается инкрементально: для каждого ребра v -> u выполняется `inDeg[u]++`.
- `allNodes` --- множество всех узлов. Необходимо, потому что некоторые узлы могут быть только целевыми (не ключами `graph`). Например, если `TGT` --- k-мер, его суффикс `GT` --- целевой узел, но из `GT` может не быть рёбер.
- `std::set` --- красно-чёрное дерево, автоматически дедуплицирует узлы.

**4. Инициализация отсутствующих степеней**
```cpp
if (!inDeg.count(v)) inDeg[v] = 0;
if (!outDeg.count(v)) outDeg[v] = 0;
```
- `map::count(key)` возвращает 0 или 1 (есть ли ключ).
- Узлы, которые есть в `allNodes`, но не были найдены как ключ `inDeg` или `outDeg`, получают степень 0.
- Без этого шага обращение `inDeg[v]` в `is1in1out` создало бы запись с 0, но `count` вернул бы 0 до этого --- логика была бы корректной, однако явная инициализация безопаснее и яснее.

**5. Лямбда `is1in1out` --- предикат для проходных узлов**
```cpp
auto is1in1out = [&](const std::string& v) {
    return inDeg[v] == 1 && outDeg[v] == 1;
};
```
- `[&]` --- захват всех переменных по ссылке. Лямбда имеет доступ к `inDeg` и `outDeg` из внешней области.
- `const std::string&` --- передача по константной ссылке, без копирования строки.
- Возвращает `bool`: true, если узел --- 1-in-1-out (проходной).
- `auto` для лямбды --- единственный способ объявить лямбду (каждая лямбда имеет уникальный анонимный тип).

**6. Фаза 1: перебор точек ветвления**
```cpp
for (auto& v : allNodes) {
    if (!is1in1out(v) && outDeg[v] > 0) {
```
- Итерируем по всем узлам. Если узел не 1-in-1-out и имеет исходящие рёбра --- это «начало» потенциального контига.
- Условие `outDeg[v] > 0` исключает стоки (вершины без исходящих рёбер): стоки --- **конец** пути, не начало.
- `graph.find(v)` вместо `graph[v]` --- чтобы не создавать пустую запись для узлов, не являющихся ключами графа.

**7. Перебор исходящих рёбер**
```cpp
for (auto& w : it->second) {
    std::vector<std::string> path = {v, w};
```
- Из каждой точки ветвления может исходить несколько рёбер (out-degree > 1). Каждое ребро начинает отдельный контиг.
- `{v, w}` --- инициализация вектора двумя элементами (initializer list, C++11).
- `it->second` --- вектор соседей (`it` --- итератор, полученный из `graph.find(v)`).

**8. Проход по 1-in-1-out узлам**
```cpp
while (is1in1out(current)) {
    auto cIt = graph.find(current);
    if (cIt == graph.end() || cIt->second.empty()) break;
    current = cIt->second[0];
    path.push_back(current);
    visited.insert(current);
}
```
- Ядро алгоритма: идём по единственному возможному пути, пока не встретим не-1-in-1-out узел.
- `cIt->second[0]` --- единственный сосед (out-degree = 1, значит вектор содержит ровно один элемент).
- `graph.find` + проверка `end()` --- защита от узлов, не являющихся ключами графа (только целевые узлы).
- `visited.insert(current)` --- помечаем узел, чтобы фаза 2 не обработала его повторно.

**9. Преобразование пути в строку**
```cpp
contigs.push_back(spellPath(path));
```
- `spellPath` собирает строку из вектора (k-1)-меров.
- `push_back` перемещает (move) результат `spellPath` в вектор контигов --- без копирования (copy elision / move semantics).

**10. Фаза 2: поиск изолированных циклов**
```cpp
if (is1in1out(v) && !visited.count(v)) {
```
- Узлы, не посещённые фазой 1, но являющиеся 1-in-1-out --- они принадлежат изолированным циклам.
- `visited.count(v)` --- O(k * log n) (поиск строки в `std::set`).
- Изолированные циклы возникают, когда подмножество k-меров образует замкнутую цепочку, не связанную с остальным графом.

**11. Обход изолированного цикла**
```cpp
while (current != v) {
    cycle.push_back(current);
    visited.insert(current);
    auto cIt = graph.find(current);
    if (cIt == graph.end()) break;
    current = cIt->second[0];
}
```
- Стартуем из v, идём по единственному исходящему ребру каждого узла, пока не вернёмся в v.
- Все узлы --- 1-in-1-out, поэтому путь обязательно замыкается.
- Сравнение строк `current != v` --- O(k) на каждую итерацию.

**12. Замыкание цикла**
```cpp
cycle.push_back(v);
contigs.push_back(spellPath(cycle));
```
- Добавляем стартовый узел в конец --- цикл замкнут.
- `spellPath` для цикла длины m+1 (m рёбер) возвращает строку длины m + (k-2). Это строка, «кодирующая» цикл --- она содержит все k-меры на рёбрах цикла, причём последний k-мер перекрывается с первым.

## Анализ сложности

### Время: O(n * k * log n)

Где n --- число k-меров, k --- длина каждого k-мера.

**Обоснование.** Алгоритм состоит из трёх этапов:

1. **Построение графа де Брёйна** --- O(n * k * log n). Для каждого из n k-меров: два вызова `substr` --- O(k), вставка в `map` --- O(k * log n) (O(log n) сравнений строк длины k-1).

2. **Подсчёт степеней** --- O(n * k * log n). Проход по всем рёбрам графа с вставками в `inDeg`, `outDeg`, `allNodes` --- всё на `map`/`set` со строковыми ключами.

3. **Поиск максимальных неветвящихся путей** --- O(|E| * k * log n). Каждое ребро обрабатывается ровно один раз (либо фазой 1, либо фазой 2). Но каждое обращение `graph.find(current)` --- O(k * log n), и `visited.insert` --- O(k * log n).

**Узкое место в коде:**
```cpp
while (is1in1out(current)) {
    auto cIt = graph.find(current);              // O(k * log n)
    if (cIt == graph.end() || cIt->second.empty()) break;
    current = cIt->second[0];                    // O(k) — копирование строки
    path.push_back(current);                     // O(k) amortized — копирование в вектор
    visited.insert(current);                     // O(k * log n)
}
```
Суммарно по всем вызовам цикл обрабатывает |E| рёбер, на каждом --- O(k * log n). Итого: **O(n * k * log n)**.

С `std::unordered_map` и `std::unordered_set` было бы O(k) амортизированно на операцию, снижая общую сложность до O(n * k).

### Память: O(n * k)

**Обоснование.** Граф хранит n рёбер, каждое --- две строки длины k-1.

**Основные структуры данных:**
```cpp
Graph graph;                         // O(n) записей, ключи O(k), значения — векторы строк O(k)
std::set<std::string> allNodes;      // до 2n узлов, каждый — строка O(k)
std::set<std::string> visited;       // до 2n узлов, каждый — строка O(k)
std::map<std::string, int> inDeg;    // до 2n записей
std::map<std::string, int> outDeg;   // до 2n записей
std::vector<std::string> contigs;    // суммарная длина всех контигов ≤ n + k (каждое ребро даёт 1 символ)
```
- Число уникальных узлов не более 2n (каждый k-мер создаёт не более двух новых (k-1)-меров).
- `std::set` и `std::map` --- красно-чёрные деревья, ~40 байт overhead на узел.
- Суммарная длина контигов = суммарная длина всех рёбер + (k-1) для каждого пути. В худшем случае (все пути длины 1) --- n * (k-1) + n = O(n * k).
- Итого: O(n * k) на граф + O(n * k) на множества + O(n * k) на контиги = **O(n * k)**.
