# k-Universal Circular String (BA3I)

## Задача

Найти k-универсальную циклическую двоичную строку.

**Вход:** целое число k
**Выход:** циклическая строка над алфавитом {0, 1}, содержащая каждый двоичный k-мер ровно один раз как подстроку (при циклическом чтении)

Формат входного файла Rosalind:
```text
4
```

**Пример:**
```
Вход: 4
Вывод: 0000110010111101
```

Длина результата всегда равна 2^k (ровно столько различных двоичных k-меров существует). Для k=4 строка `0000110010111101` содержит все 16 двоичных 4-меров: `0000`, `0001`, `0011`, `0110`, `1100`, `1001`, `0010`, `0101`, `1011`, `0111`, `1111`, `1110`, `1101`, `1010`, `0100`, `1000` — последние из них «оборачиваются» через конец строки.

## Теория

### Последовательности де Брёйна

**Последовательность де Брёйна** B(n, k) — кратчайшая циклическая строка над алфавитом размера n, содержащая каждую строку длины k из этого алфавита ровно один раз в качестве подстроки. Для двоичного алфавита (n=2) длина такой строки равна 2^k.

Нидерландский математик Николаас Говерт де Брёйн доказал в 1946 году, что число различных последовательностей де Брёйна B(2, k) равно 2^(2^(k-1) - k). Например, для k=4 существует 2^(8-4) = 16 различных последовательностей.

### Связь с графом де Брёйна

Задача сводится к нахождению эйлерова цикла в графе де Брёйна над двоичным алфавитом:

- **Вершины:** все двоичные строки длины (k-1). Их 2^(k-1). Каждую вершину удобно представлять целым числом от 0 до 2^(k-1)-1.
- **Рёбра:** все двоичные строки длины k. Их 2^k. Ребро, соответствующее k-меру s, идёт из вершины prefix(s) = s[0..k-2] в вершину suffix(s) = s[1..k-1].
- **Структура:** вершина с номером i имеет ровно два исходящих ребра — в вершины (2i) mod 2^(k-1) (дописываем 0) и (2i+1) mod 2^(k-1) (дописываем 1). И ровно два входящих.

Поскольку каждая вершина имеет in-degree = out-degree = 2, граф гарантированно имеет эйлеров цикл (теорема Эйлера). Эйлеров цикл проходит каждое ребро ровно раз, а каждое ребро — это двоичный k-мер. Значит, строка, «прочитанная» по эйлерову циклу, содержит все 2^k двоичных k-меров.

### Как прочитать строку по циклу

Каждое ребро цикла добавляет один символ: последний бит целевой вершины. Если цикл проходит через вершины v_0, v_1, ..., v_{2^k}, то циклическая строка — конкатенация последних битов v_1, v_2, ..., v_{2^k}. Последний бит вершины u — это `u & 1` (побитовое И с единицей).

## Применение

### В биологии

- **Дизайн ДНК-микрочипов.** Микрочип (DNA microarray) содержит короткие ДНК-зонды (probes), каждый из которых гибридизуется с комплементарной последовательностью. Для полного покрытия всех возможных k-меров нужен «универсальный» набор зондов. Последовательность де Брёйна B(4, k) (алфавит {A, C, G, T}) минимизирует длину одноцепочечной ДНК, содержащей все k-меры. Для k=10 вместо 4^10 = 1 048 576 отдельных зондов достаточно одной молекулы длиной ~1 Мб. Компания Affymetrix использовала эту идею для создания высокоплотных чипов GeneChip.

- **Универсальный дизайн праймеров.** При проектировании дегенеративных праймеров для ПЦР (polymerase chain reaction) de Bruijn-последовательности позволяют покрыть все варианты связующей области минимальным числом олигонуклеотидов. Это важно при изучении метагеномов, где последовательность целевого гена заранее неизвестна.

- **Эксперименты в нейробиологии.** Последовательности де Брёйна используются для генерации визуальных стимулов в экспериментах с записью активности нейронов. Каждый возможный k-элементный контекст встречается ровно один раз, что обеспечивает равномерное покрытие стимульного пространства. Группа Gallant (UC Berkeley, 2011) использовала этот подход для картирования рецептивных полей зрительной коры.

### В других областях

- **Взлом PIN-кодов.** Некоторые электронные замки проверяют последние k введённых цифр после каждого нажатия (без кнопки «Enter»). Для перебора всех 10^k комбинаций k-значного PIN наивный подход требует k * 10^k нажатий, а последовательность де Брёйна B(10, k) — всего 10^k + (k-1) нажатий. Для 4-значного PIN: 10 003 нажатия вместо 40 000 — ускорение в ~4 раза.

- **Тестирование цифровых схем (LFSR).** Линейный регистр сдвига с обратной связью (Linear Feedback Shift Register) генерирует последовательности, близкие к де Брёйновым. При тестировании цифровых схем такие последовательности гарантируют, что каждый возможный k-битный вход был подан хотя бы раз. Стандарт IEEE 1149.1 (JTAG) использует LFSR для генерации тестовых паттернов.

- **Карточные фокусы.** Математик-фокусник раскладывает 2^k карт (красных и чёрных) в круг по последовательности де Брёйна. Зритель указывает на k последовательных карт, фокусник мгновенно определяет их позицию — каждая последовательность из k цветов уникальна. Мартин Гарднер описал этот фокус в колонке Scientific American (1968).

- **Робототехника и позиционирование.** Абсолютные позиционные энкодеры используют де Брёйнову последовательность на диске: k оптических датчиков считывают k последовательных бит, и каждое положение диска даёт уникальный k-битный код. Это позволяет определить угол поворота сразу после включения, без калибровки. Компания Renishaw использует этот принцип в промышленных энкодерах.

## Алгоритм

### Идея

Ключевое наблюдение: задача о k-универсальной циклической строке — это задача об эйлеровом цикле в графе де Брёйна над двоичным алфавитом. Вместо работы со строками мы кодируем вершины числами: (k-1)-битная строка `b_{k-2}...b_1 b_0` — это число от 0 до 2^(k-1)-1. Тогда два ребра из вершины i ведут в:
- `(2i) mod 2^(k-1)` — сдвиг влево + бит 0 (дописать 0 справа, отбросить старший бит)
- `(2i + 1) mod 2^(k-1)` — сдвиг влево + бит 1 (дописать 1 справа, отбросить старший бит)

Находим эйлеров цикл алгоритмом Хирхольцера, затем «прочитываем» строку: каждое ребро v->u вносит один символ — последний бит u.

Почему результат циклический? Эйлеров цикл возвращается в стартовую вершину, но мы не записываем символ возврата — получается строка длины 2^k. При циклическом чтении последние (k-1) символов «оборачиваются» через начало, формируя оставшиеся k-меры.

### Псевдокод
```
kUniversalCircular(k):
    numNodes ← 2^(k-1)

    // Построить граф де Брёйна
    for i ← 0 to numNodes-1:
        graph[i] ← [(2i) mod numNodes, (2i+1) mod numNodes]

    // Эйлеров цикл (Хирхольцер)
    edgeIndex ← {v: 0 для каждой вершины v}
    stack ← [0]
    cycle ← []

    while stack не пуст:
        v ← stack.back()
        if edgeIndex[v] < |graph[v]|:
            u ← graph[v][edgeIndex[v]]
            edgeIndex[v] += 1
            stack.push(u)
        else:
            cycle.push(v)
            stack.pop()

    reverse(cycle)

    // Прочитать строку: последний бит каждой целевой вершины
    result ← ""
    for i ← 0 to |cycle|-2:
        result += (cycle[i+1] & 1)

    return result
```

## Реализация на C++

```cpp
std::string solve(const InputData& input) {
    size_t k = input.k;
    int numNodes = 1 << (k - 1);                              // (1)

    std::map<int, std::vector<int>> graph;                     // (2)
    for (int i = 0; i < numNodes; ++i) {
        graph[i].push_back((i * 2) % numNodes);               // (3)
        graph[i].push_back((i * 2 + 1) % numNodes);
    }

    std::map<int, size_t> edgeIndex;                           // (4)
    for (auto& [v, _] : graph)
        edgeIndex[v] = 0;

    std::vector<int> stack = {0};                              // (5)
    std::vector<int> cycle;

    while (!stack.empty()) {                                   // (6)
        int v = stack.back();
        if (edgeIndex[v] < graph[v].size()) {
            int u = graph[v][edgeIndex[v]++];                  // (7)
            stack.push_back(u);
        } else {
            cycle.push_back(v);                                // (8)
            stack.pop_back();
        }
    }

    std::reverse(cycle.begin(), cycle.end());                  // (9)

    std::string result;                                        // (10)
    for (size_t i = 0; i + 1 < cycle.size(); ++i) {
        result += ('0' + (cycle[i + 1] & 1));                 // (11)
    }

    return result;
}
```

## Разбор кода

**1. Вычисление числа вершин битовым сдвигом**
```cpp
int numNodes = 1 << (k - 1);
```
- `1 << (k - 1)` — побитовый сдвиг единицы влево на (k-1) позиций, эквивалентно 2^(k-1).
- Для k=4: `1 << 3` = 8 вершин (двоичные строки длины 3: `000`, `001`, ..., `111`).
- Используется `int`, а не `size_t`, потому что вершины графа — целые числа, используемые как ключи в `std::map<int, ...>`. Для k <= 20 значение 2^19 = 524 288 гарантированно помещается в `int`.

**2. Представление графа**
```cpp
std::map<int, std::vector<int>> graph;
```
- Список смежности: ключ — номер вершины, значение — вектор соседей. Каждая вершина имеет ровно 2 соседа (out-degree = 2 для двоичного алфавита).
- `std::map` используется для совместимости с алгоритмом Хирхольцера из BA3F. Для чисто числовых вершин `std::vector<std::vector<int>>` был бы эффективнее (O(1) доступ vs O(log n)), но граф мал: максимум 2^19 вершин для k=20.

**3. Построение рёбер двоичного сдвига**
```cpp
graph[i].push_back((i * 2) % numNodes);
graph[i].push_back((i * 2 + 1) % numNodes);
```
- `i * 2` — сдвиг бинарного представления i влево на 1 бит (дописать 0 справа).
- `i * 2 + 1` — сдвиг влево + установка младшего бита (дописать 1 справа).
- `% numNodes` — отбросить старший бит, оставив (k-1) младших. Это эквивалентно `suffix(prefix + bit)`.
- Пример для k=4, i=5 (двоичное `101`): ребро в `(10*1) % 8 = 2` (`010`) и `(11) % 8 = 3` (`011`).

**4. Индексы непройденных рёбер**
```cpp
std::map<int, size_t> edgeIndex;
for (auto& [v, _] : graph)
    edgeIndex[v] = 0;
```
- Structured binding `[v, _]` — C++17: `v` получает ключ, `_` — список соседей (не используется).
- `edgeIndex[v] = 0` — ни одно ребро из v ещё не пройдено. По мере обхода индекс инкрементируется: когда `edgeIndex[v] == graph[v].size()`, все рёбра из v пройдены.

**5. Инициализация стека со стартовой вершиной 0**
```cpp
std::vector<int> stack = {0};
```
- `{0}` — инициализация через `initializer_list`, вектор с одним элементом 0.
- Старт с вершины 0 (двоичная `000...0`) — произвольный выбор, для эйлерова цикла результат не зависит от стартовой вершины (цикл замкнут).

**6. Главный цикл Хирхольцера**
```cpp
while (!stack.empty()) {
    int v = stack.back();
```
- Стековая реализация алгоритма Хирхольцера (подробный разбор — в BA3F).
- Каждая итерация: либо продвигаемся по непройденному ребру (push), либо фиксируем вершину в результате (pop).

**7. Постфиксный инкремент при взятии ребра**
```cpp
int u = graph[v][edgeIndex[v]++];
```
- `edgeIndex[v]++` — постфиксный инкремент: сначала возвращается текущее значение (используется как индекс для `graph[v][...]`), потом значение увеличивается на 1.
- Это компактная запись: взять ребро и пометить его как пройденное за одну операцию.
- Сравните с раздельной записью из BA3F:
  ```cpp
  int u = graph[v][edgeIndex[v]];
  edgeIndex[v]++;
  ```

**8. Фиксация вершины при возврате**
```cpp
cycle.push_back(v);
stack.pop_back();
```
- Когда из вершины v все рёбра пройдены — она фиксируется в `cycle` и удаляется из стека.
- Запись идёт в обратном порядке обхода; подциклы вшиваются автоматически (см. BA3F).

**9. Разворот результата**
```cpp
std::reverse(cycle.begin(), cycle.end());
```
- Вершины записывались при разматывании стека (в обратном порядке) — нужен `reverse` для восстановления прямого порядка обхода. O(2^k) операций.

**10-11. Чтение строки из цикла**
```cpp
std::string result;
for (size_t i = 0; i + 1 < cycle.size(); ++i) {
    result += ('0' + (cycle[i + 1] & 1));
}
```
- `cycle[i + 1] & 1` — побитовое И с 1, извлекает младший бит числа. Это последний символ двоичного представления вершины.
- `'0' + (...)` — преобразование 0/1 в символ '0'/'1'. ASCII-код '0' = 48, '0'+1 = '1'.
- `i + 1 < cycle.size()` вместо `i < cycle.size() - 1` — безопасное сравнение: если `cycle` пуст, `cycle.size() - 1` даст переполнение `size_t` (беззнаковый тип), а `i + 1 < cycle.size()` корректно вернёт `false`.
- Цикл `cycle` содержит 2^k + 1 вершину (последняя = первая), поэтому результат — 2^k символов.

## Анализ сложности

### Время: O(2^k)

**Обоснование.** Граф содержит 2^(k-1) вершин и 2^k рёбер. Каждый шаг алгоритма выполняется за O(1) (амортизированно), и общее число шагов пропорционально числу рёбер.

**Узкое место в коде — главный цикл Хирхольцера:**
```cpp
while (!stack.empty()) {                              // суммарно O(2^k) итераций
    int v = stack.back();                              // O(1)
    if (edgeIndex[v] < graph[v].size()) {
        int u = graph[v][edgeIndex[v]++];              // O(1) — доступ по индексу + инкремент
        stack.push_back(u);                            // O(1) амортизированно
    } else {
        cycle.push_back(v);                            // O(1) амортизированно
        stack.pop_back();                              // O(1)
    }
}
```
Цикл выполняется ровно 2^k + 2^(k-1) раз: 2^k итераций для продвижения по рёбрам и 2^(k-1) итераций для фиксации вершин (при условии что каждая вершина посещается дважды в среднем). Все операции внутри — O(1).

Дополнительные затраты:
- Построение графа: O(2^(k-1)) — по две вставки на вершину
- `std::reverse`: O(2^k) — переворот вектора из 2^k + 1 элемент
- Чтение строки: O(2^k) — один проход по циклу

Итого: O(2^k). Это **оптимально** — длина результата равна 2^k, поэтому любой алгоритм требует хотя бы O(2^k) для записи ответа. Для k=20 это ~10^6 операций (миллисекунды на современном процессоре).

**Замечание по `std::map` vs `std::vector`:** использование `std::map<int, ...>` добавляет множитель O(log n) к доступу по ключу. Для данной задачи это O(log 2^(k-1)) = O(k). Общая сложность формально O(k * 2^k). На практике для k <= 20 разница несущественна, но для максимальной производительности можно заменить `map` на `vector`:
```cpp
std::vector<std::vector<int>> graph(numNodes);  // O(1) доступ вместо O(log n)
std::vector<size_t> edgeIndex(numNodes, 0);
```

### Память: O(2^k)

**Обоснование.** Все основные структуры данных пропорциональны размеру графа:

```cpp
std::map<int, std::vector<int>> graph;   // O(2^(k-1) + 2^k) = O(2^k) — вершины + рёбра
std::map<int, size_t> edgeIndex;         // O(2^(k-1)) — по одному индексу на вершину
std::vector<int> stack;                  // O(2^k) в худшем случае
std::vector<int> cycle;                  // O(2^k + 1) — эйлеров цикл
std::string result;                      // O(2^k) — выходная строка
```

Суммарно: O(2^k). Для k=20 это ~4 МБ (10^6 элементов по ~4 байта каждый) — легко помещается в оперативную память.
