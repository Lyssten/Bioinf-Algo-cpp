# Construct a String Spelled by a Gapped Genome Path (BA3L)

## Задача

Реконструировать строку по пути из спаренных ридов (gapped genome path).

**Вход:** целые числа k и d, последовательность (k,d)-меров (пар k-меров с известным расстоянием d между ними)
**Выход:** строка, определяемая данным путём из спаренных ридов

Формат входного файла Rosalind:
```text
4 2
GACC|GCGC
ACCG|CGCC
CCGA|GCCG
CGAG|CCGG
GAGC|CGGA
```

**Пример:**
```
Вход:
4 2
GACC|GCGC
ACCG|CGCC
CCGA|GCCG
CGAG|CCGG
GAGC|CGGA

Вывод: GACCGAGCGCCGGA
```

## Теория

### Парные риды (paired reads)

При парном секвенировании (paired-end sequencing) каждый фрагмент ДНК читается с двух концов. Результат — пара коротких последовательностей (ридов) с известным расстоянием между ними. Формально, **(k,d)-мер** — это пара k-меров (a, b), где a начинается на позиции i в геноме, а b начинается на позиции i + k + d:

```
Геном:  G A C C G A G C G C C G G A
        |-------|                          ← первый рид (k=4): GACC
                    |-------|              ← второй рид (k=4): GCGC
        |←  k  →|←  d  →|←  k  →|
              k + d = 6
```

Между двумя ридами находится промежуток (gap) длиной d. Зная k и d, мы точно знаем, на каком расстоянии друг от друга расположены два рида в исходном геноме.

### Путь из спаренных ридов

Последовательность (k,d)-меров образует **путь**, если:
- Суффикс первого компонента каждого (k,d)-мера совпадает с префиксом первого компонента следующего
- Суффикс второго компонента каждого (k,d)-мера совпадает с префиксом второго компонента следующего

Это аналог задачи BA3B (реконструкция строки по пути генома), но для парных ридов. В BA3B мы «прочитывали» одну цепочку k-меров, здесь — две параллельные цепочки, смещённые на (k+d) позиций.

### Реконструкция строки

Из первых компонентов собирается строка `firstStr`, из вторых — `secondStr`. Результирующая строка генома:

```
Позиции:   0   1   2   ...  n-1  n  n+1  ...  n+k+d-1
           |--- firstStr ---|
                             |--- overlap ---|
                     k+d позиций отступа
                             |--- secondStr ---|
```

Строка `secondStr` начинается на позиции (k+d) в геноме. Поэтому суффикс `firstStr` и префикс `secondStr` должны совпадать в области перекрытия. Если они не совпадают — входные данные некорректны.

Длина перекрытия: `overlap = |firstStr| - k - d`. Результат: `firstStr + secondStr[overlap:]`.

## Применение

### В биологии

- **Парное секвенирование Illumina.** Платформы Illumina (HiSeq, NovaSeq) — доминирующая технология секвенирования, производящая ~90% мировых данных. Каждый прогон генерирует миллиарды парных ридов длиной 2x150 bp с insert size 300--500 bp. Знание расстояния между парными ридами позволяет разрешать повторы длиной до insert size, что невозможно с одиночными ридами. Для генома *E. coli* (4.6 Мб) парные риды при insert size 500 bp разрешают ~95% повторов.

- **Скаффолдинг в сборке геномов.** После построения контигов (непрерывных фрагментов) из обычного графа де Брёйна парные риды используются для объединения контигов в скаффолды — упорядоченные цепочки контигов с известными расстояниями между ними. Программа **SOAPdenovo2** использует парные риды с различными insert size (200 bp, 2 Kbp, 5 Kbp, 10 Kbp) для иерархического скаффолдинга. Для генома панды (*Ailuropoda melanoleuca*, 2.4 Гб) это позволило собрать скаффолды N50 = 1.3 Мб из ридов длиной всего 2x45 bp.

- **Обнаружение структурных вариаций.** Когда наблюдаемое расстояние между парными ридами отличается от ожидаемого insert size, это сигнализирует о структурной вариации: делеции (расстояние больше ожидаемого), инсерции (расстояние меньше), инверсии (изменение ориентации). Программы **BreakDancer** и **DELLY** используют дискордантные парные риды для обнаружения структурных вариаций в раковых геномах.

### В других областях

- **Стереозрение в робототехнике.** Две камеры, разнесённые на известное расстояние (аналог параметра d), снимают одну сцену. Из каждого кадра извлекаются локальные признаки (аналог k-меров), затем парные признаки сопоставляются для восстановления 3D-структуры сцены. Автопилоты Tesla используют стереопары камер для определения расстояний до объектов с точностью до нескольких сантиметров.

- **Сшивание панорамных изображений.** Спутниковые снимки перекрывающихся полос поверхности Земли (как парные риды перекрываются в геноме) сшиваются в единую карту. Каждый снимок имеет известное смещение (аналог d). Сервисы Google Earth и Yandex Maps сшивают миллионы таких полос, верифицируя совпадение в зонах перекрытия — та же логика, что проверка `overlap` в нашем коде.

- **Выравнивание временных рядов.** В обработке сигналов два датчика с известным временным сдвигом записывают один и тот же процесс. Совмещение двух записей требует проверки согласованности в зоне перекрытия и конкатенации — алгоритмически идентично нашей задаче.

## Алгоритм

### Идея

Задача решается в три этапа:

1. **Spell первую строку.** Из первых компонентов (k,d)-меров собрать строку по пути (как в BA3B): взять первый k-мер целиком, от каждого следующего дописать последний символ.

2. **Spell вторую строку.** Аналогично из вторых компонентов.

3. **Совместить и проверить.** Вторая строка начинается на позиции (k+d) в геноме. Суффикс первой строки (позиции от k+d до конца) должен совпадать с префиксом второй строки. Если совпадает — склеить. Если нет — ошибка во входных данных.

Почему нужна проверка? На практике парные риды могут содержать ошибки секвенирования, и область перекрытия — это «двойная проверка» согласованности. В учебной задаче вход гарантированно корректен, но проверка важна для надёжности кода.

### Псевдокод
```
StringSpelledByGappedPatterns(k, d, reads):
    firstStr ← reads[0].first
    secondStr ← reads[0].second

    for i ← 1 to |reads|-1:
        firstStr += последний символ reads[i].first
        secondStr += последний символ reads[i].second

    overlap ← |firstStr| - k - d

    for i ← 0 to overlap-1:
        if firstStr[k + d + i] ≠ secondStr[i]:
            error("Несовпадение в области перекрытия")

    return firstStr + secondStr[overlap:]
```

## Реализация на C++

```cpp
std::string solve(const InputData& input) {
    std::string firstStr = input.reads[0].first;               // (1)
    std::string secondStr = input.reads[0].second;

    for (size_t i = 1; i < input.reads.size(); ++i) {          // (2)
        firstStr += input.reads[i].first.back();               // (3)
        secondStr += input.reads[i].second.back();
    }

    size_t k = input.k;                                        // (4)
    size_t d = input.d;
    size_t overlap = firstStr.size() - k - d;                  // (5)

    for (size_t i = 0; i < overlap; ++i) {                     // (6)
        if (firstStr[k + d + i] != secondStr[i])
            throw std::runtime_error("Mismatch at overlap position");
    }

    return firstStr + secondStr.substr(overlap);                // (7)
}
```

## Разбор кода

**1. Инициализация первых k-мерами**
```cpp
std::string firstStr = input.reads[0].first;
std::string secondStr = input.reads[0].second;
```
- Берём первые компоненты нулевого (k,d)-мера как начальные строки.
- `input.reads[0].first` — доступ к полю `first` структуры `PairedRead`:
  ```cpp
  struct PairedRead {
      std::string first;
      std::string second;
  };
  ```
- Копирование строк (а не ссылка), потому что `firstStr` и `secondStr` будут расти.

**2. Цикл прочитывания строк**
```cpp
for (size_t i = 1; i < input.reads.size(); ++i) {
```
- Начинаем с индекса 1 (нулевой уже использован для инициализации).
- `input.reads.size()` возвращает `size_t`, поэтому счётчик тоже `size_t` — нет предупреждения о сравнении знаковых/беззнаковых типов.

**3. Дописывание последнего символа**
```cpp
firstStr += input.reads[i].first.back();
secondStr += input.reads[i].second.back();
```
- `std::string::back()` — O(1) доступ к последнему символу строки (C++11).
- `operator+=` для `char` — дописывает один символ в конец строки. Амортизированно O(1).
- Это эквивалент «прочитывания пути» из BA3B: каждый следующий k-мер в пути перекрывается с предыдущим на (k-1) символов, уникален только последний символ.
- Для примера: `GACC` -> `ACCG` (overlap `ACC`, новый символ `G`) -> `CCGA` (overlap `CGA`, новый символ `A`).

**4. Локальные копии k и d**
```cpp
size_t k = input.k;
size_t d = input.d;
```
- Создание локальных копий для краткости — `k` вместо `input.k`.
- Обе переменные `size_t`, как и поля структуры `InputData`, что предотвращает неявные преобразования типов.

**5. Вычисление длины перекрытия**
```cpp
size_t overlap = firstStr.size() - k - d;
```
- `firstStr` имеет длину `k + (n-1)`, где n — число (k,d)-меров. `secondStr` — аналогично.
- Вторая строка начинается на позиции (k+d) в геноме. Поэтому `firstStr[k+d..]` и `secondStr[0..overlap-1]` должны совпадать.
- `overlap = (k + n - 1) - k - d = n - 1 - d`. Для примера: `firstStr` = `GACCGAGC` (длина 8), k=4, d=2, overlap = 8 - 4 - 2 = 2. Действительно, `firstStr[6..7]` = `GC` и `secondStr[0..1]` = `GC` совпадают.
- Важно: если `firstStr.size() < k + d`, то `overlap` переполнится (underflow `size_t`). На практике это значит, что путь слишком короткий для данных k и d — программа упадёт с ошибкой при обращении к `firstStr[k + d + i]`.

**6. Проверка согласованности**
```cpp
for (size_t i = 0; i < overlap; ++i) {
    if (firstStr[k + d + i] != secondStr[i])
        throw std::runtime_error("Mismatch at overlap position");
}
```
- Посимвольная проверка, что суффикс `firstStr` (начиная с позиции k+d) совпадает с префиксом `secondStr` (длиной `overlap`).
- `std::runtime_error` — стандартное исключение для ошибок времени выполнения. Наследует от `std::exception`, перехватывается в `main()` через `catch (const std::exception&)`.
- В учебной задаче Rosalind входные данные всегда корректны, но проверка полезна при отладке: ошибка в парсинге или неправильные k/d сразу обнаруживаются.

**7. Конкатенация результата**
```cpp
return firstStr + secondStr.substr(overlap);
```
- `std::string::substr(pos)` — возвращает подстроку от позиции `pos` до конца. Создаёт новый `std::string`.
- `firstStr + ...` — конкатенация строк через `operator+`. Создаёт ещё одну строку.
- Для примера: `firstStr` = `GACCGAGC`, `secondStr.substr(2)` = `CCGGA` -> результат `GACCGAGCGCCGGA`.
- Альтернатива без лишнего копирования: `firstStr.append(secondStr, overlap, std::string::npos)` — дописывает `secondStr[overlap:]` непосредственно к `firstStr`, избегая создания промежуточной строки. Для геномных данных (миллионы символов) это экономит один аллокацию.

## Анализ сложности

### Время: O(n * k)

Здесь n — число (k,d)-меров во входном пути.

**Обоснование.** Алгоритм состоит из трёх линейных проходов:

**Узкое место 1 — сборка строк (amortized O(n)):**
```cpp
for (size_t i = 1; i < input.reads.size(); ++i) {     // n-1 итераций
    firstStr += input.reads[i].first.back();            // O(1) амортизированно
    secondStr += input.reads[i].second.back();          // O(1) амортизированно
}
```
Каждая итерация добавляет один символ к строке. `std::string::operator+=` для `char` работает за O(1) амортизированно (аналогично `std::vector::push_back` — удвоение буфера при переполнении).

**Узкое место 2 — проверка перекрытия (O(n)):**
```cpp
for (size_t i = 0; i < overlap; ++i) {                 // overlap = n - 1 - d итераций
    if (firstStr[k + d + i] != secondStr[i])            // O(1) — доступ по индексу
```
Посимвольное сравнение двух подстрок длиной `overlap`. В худшем случае (полное совпадение) — `n - 1 - d` сравнений.

**Узкое место 3 — конкатенация результата (O(n + k)):**
```cpp
return firstStr + secondStr.substr(overlap);            // O(|firstStr| + |secondStr| - overlap)
```
`substr` создаёт строку длиной `k + d`, `operator+` копирует обе строки. Суммарная длина результата: `k + (n-1) + k + d = 2k + d + n - 1`.

Считывание парных ридов из файла — O(n * k): каждый рид длиной k, и их n штук. Поэтому общая сложность с учётом ввода — O(n * k).

### Память: O(n + k)

**Обоснование.** Основные структуры данных:

```cpp
std::vector<PairedRead> reads;   // O(n * k) — входные данные (n пар строк по k символов)
std::string firstStr;            // O(n + k) — собранная первая строка
std::string secondStr;           // O(n + k) — собранная вторая строка
std::string result;              // O(n + k + d) — выходная строка
```

Доминирует входной вектор `reads` — O(n * k). Если не считать входные данные (они уже в памяти), дополнительная память — O(n + k + d) для трёх строк.

Для типичных данных Rosalind (n ~ 5000, k ~ 50, d ~ 200) потребление памяти: ~500 Кб для ридов + ~10 Кб для строк — пренебрежимо мало.
