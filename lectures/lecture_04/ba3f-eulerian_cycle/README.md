# Eulerian Cycle (BA3F)

## Задача

Найти эйлеров цикл в ориентированном графе.

**Вход:** список смежности ориентированного графа
**Выход:** эйлеров цикл в виде последовательности вершин

Формат входного файла Rosalind:
```text
0 -> 3
1 -> 0
2 -> 1,6
3 -> 2
4 -> 2
5 -> 4
6 -> 5,8
7 -> 9
8 -> 7
9 -> 6
```

**Пример:**
```
Вход:
0 -> 3
1 -> 0
2 -> 1,6
3 -> 2
4 -> 2
5 -> 4
6 -> 5,8
7 -> 9
8 -> 7
9 -> 6

Вывод: 6->8->7->9->6->5->4->2->1->0->3->2->6
```

## Теория

### Задача о Кёнигсбергских мостах

В 1736 году Леонард Эйлер доказал, что невозможно обойти все 7 мостов Кёнигсберга (ныне Калининград), пройдя по каждому ровно один раз и вернувшись в начальную точку. Так родилась теория графов. Эйлер показал, что такой обход возможен тогда и только тогда, когда каждая вершина имеет чётную степень. Для мостов Кёнигсберга три вершины имели степень 3 — обход невозможен.

### Эйлеров цикл vs эйлеров путь vs гамильтонов путь

| Понятие | Проходит через... | Сложность |
|---|---|---|
| **Эйлеров путь** | каждое **ребро** ровно раз, начало ≠ конец | O(\|E\|) |
| **Эйлеров цикл** | каждое **ребро** ровно раз, начало = конец | O(\|E\|) |
| **Гамильтонов путь** | каждую **вершину** ровно раз | NP-полная |

Принципиальная разница: эйлеровы задачи решаются за линейное время, гамильтоновы — экспоненциально. Именно поэтому в сборке генома перешли от overlap-графа (гамильтонов путь, BA3C) к графу де Брёйна (эйлеров путь, BA3F).

### Теорема Эйлера (для ориентированных графов)

Ориентированный граф имеет эйлеров цикл тогда и только тогда, когда:
1. **Связность:** все вершины с ненулевой степенью принадлежат одной компоненте сильной связности
2. **Баланс степеней:** для каждой вершины `in-degree = out-degree`

Для эйлерова пути (не цикла) допускаются ровно две «несбалансированные» вершины: одна с `out − in = 1` (старт) и одна с `in − out = 1` (финиш).

### Алгоритм Хирхольцера (Hierholzer, 1873)

Классический двухфазный алгоритм:
1. Стартуем из любой вершины, идём по непосещённым рёбрам, пока не вернёмся в начало → начальный цикл
2. Если остались непройденные рёбра — находим вершину на текущем цикле с непройденными рёбрами, строим из неё подцикл и вшиваем его в основной

**Стековая реализация** (используемая в нашем коде) элегантно объединяет обе фазы в один цикл:
- Идём вперёд, пока есть непройденные рёбра → кладём вершины на стек
- Когда рёбер нет → снимаем вершину со стека и добавляем в результат
- Подциклы автоматически вшиваются в правильные позиции

Почему это работает? Когда мы заходим в вершину, у которой есть боковое ответвление (подцикл), мы сначала **полностью** обходим подцикл, прежде чем вернуться к основному маршруту. Результат записывается в обратном порядке при разматывании стека, поэтому в конце нужен `reverse`.

## Применение

### В биологии

- **Финальный шаг сборки генома.** Вся цепочка задач лекции 4 складывается в конвейер ассемблера:
  1. Секвенатор → k-меры (BA3A)
  2. k-меры → граф де Брёйна (BA3E)
  3. Граф де Брёйна → **эйлеров путь/цикл** → реконструированный геном

  Если геном кольцевой (бактерии, митохондриальная ДНК, плазмиды) — ищем эйлеров цикл. Например, геном *E. coli* (4.6 Мб) — одна кольцевая хромосома. Плазмида pUC19 (2.7 Кб) — тоже кольцевая.

- **Реальные ограничения.** На практике граф де Брёйна реального генома **не имеет единственного эйлерова пути** из-за: (1) повторов в геноме, (2) ошибок секвенирования (создают «тупиковые» рёбра), (3) неполного покрытия (пропущенные рёбра). Ассемблеры разбивают граф на **контиги** — максимальные подграфы с однозначным эйлеровым путём. SPAdes для *E. coli* генерирует ~100–200 контигов, которые потом соединяются в скаффолды с помощью парных ридов.

- **Circularization.** Для кольцевых геномов бактерий ассемблер ищет именно эйлеров **цикл**, а не путь. Программа **Unicycler** (2017) специализируется на сборке кольцевых бактериальных геномов: она итеративно строит графы де Брёйна при разных k и ищет эйлеров цикл, дающий замкнутый геном. Для *Staphylococcus aureus* (2.8 Мб) Unicycler воспроизводит полную кольцевую хромосому.

### В других областях

- **Задача китайского почтальона (Chinese Postman Problem).** Почтальону нужно обойти все улицы района, минимизируя повторные проходы. Если граф улиц эйлеров — оптимальный маршрут = эйлеров цикл (каждая улица пройдена ровно один раз). В городе Кёнигсберге это было невозможно, но, например, сеть улиц шахматного порядка (Manhattan grid) — эйлерова. Городские службы (снегоуборка, мусоровоз, уличная уборка) решают эту задачу ежедневно. В Москве для ~35 000 улиц задача решается за доли секунды.

- **Тестирование печатных плат.** Робот-тестер должен проверить каждое соединение на плате ровно один раз. Соединения — рёбра, контактные площадки — вершины. Эйлеров цикл даёт оптимальный маршрут тестирования, минимизирующий перемещения. Для современного процессора (~10⁹ транзисторов, ~10⁶ тестируемых соединений) это экономит часы тестового времени.

- **Генерация последовательностей де Брёйна.** Эйлеров цикл в графе де Брёйна порядка n даёт кратчайшую циклическую строку, содержащую все n-граммы. Применение — тестирование PIN-кодов: для перебора всех 4-значных PIN (10⁴ = 10 000 комбинаций) вместо 40 000 нажатий достаточно 10 003 (10 000 + 3 для первого PIN). Также используется при тестировании регистров сдвига в FPGA.

- **Рисование одним росчерком.** Классическая головоломка: нарисовать фигуру, не отрывая карандаша и не проходя по линии дважды. Решение существует ⟺ граф фигуры эйлеров. Домик (4 треугольника + квадрат) можно нарисовать одним росчерком, потому что ровно 2 вершины имеют нечётную степень — эйлеров путь.

## Алгоритм

### Идея

Стековая реализация Хирхольцера использует два контейнера: `stack` (текущий путь) и `cycle` (результат). Вместо удаления пройденных рёбер из графа (дорого — O(n) для вектора) мы отслеживаем индекс следующего непройденного ребра для каждой вершины в массиве `edgeIndex`.

Пошаговый пример для графа `0→3, 3→2, 2→1, 1→0, 2→6, 6→5, 5→4, 4→2, 6→8, 8→7, 7→9, 9→6`:
```
Шаг 1: stack=[6], идём 6→5→4→2→1→0→3→2→6 (вернулись!)
        но у 2 и 6 есть непройденные рёбра
Шаг 2: стек разматывается: 6 → cycle
        у 2 есть ребро → идём 2→6→8→7→9→6 (вернулись!)
Шаг 3: разматывание: 6,9,7,8,6,2 → cycle
Шаг 4: продолжаем разматывание основного пути: ...1,0,3,2 → cycle
Результат (после reverse): 6→8→7→9→6→5→4→2→1→0→3→2→6
```

### Псевдокод
```
EulerianCycle(graph):
    edgeIndex ← {v: 0 для каждой вершины v}
    stack ← [startNode]
    cycle ← []

    while stack не пуст:
        v ← stack.back()
        if edgeIndex[v] < |graph[v]|:       // есть непройденные рёбра
            u ← graph[v][edgeIndex[v]]
            edgeIndex[v] += 1
            stack.push(u)
        else:                                // все рёбра пройдены
            cycle.push(v)
            stack.pop()

    reverse(cycle)
    return cycle
```

## Реализация на C++

```cpp
std::vector<int> eulerianCycle(std::map<int, std::vector<int>>& graph) {
    std::map<int, size_t> edgeIndex;                       // (1)
    for (auto& [node, neighbors] : graph) {
        edgeIndex[node] = 0;
    }

    int startNode = graph.begin()->first;                  // (2)
    std::vector<int> stack;                                // (3)
    std::vector<int> cycle;

    stack.push_back(startNode);

    while (!stack.empty()) {                               // (4)
        int v = stack.back();
        if (edgeIndex[v] < graph[v].size()) {              // (5)
            int u = graph[v][edgeIndex[v]];
            edgeIndex[v]++;
            stack.push_back(u);
        } else {
            cycle.push_back(v);                            // (6)
            stack.pop_back();
        }
    }

    std::reverse(cycle.begin(), cycle.end());              // (7)
    return cycle;
}
```

## Разбор кода

**1. `edgeIndex` — индекс следующего непройденного ребра**
```cpp
std::map<int, size_t> edgeIndex;
for (auto& [node, neighbors] : graph) {
    edgeIndex[node] = 0;
}
```
- Вместо удаления пройденных рёбер из `graph[v]` (O(n) для каждого удаления из начала вектора) мы храним индекс текущего ребра. `edgeIndex[v] = 3` означает: первые 3 ребра из v уже пройдены, следующее — `graph[v][3]`.
- Это O(1) на «удаление» ребра вместо O(n). Разница критична: для графа с 10⁶ рёбер это O(10⁶) vs O(10¹²).
- `size_t` — потому что индексирует `std::vector`, чей `size()` возвращает `size_t`.

**2. Выбор стартовой вершины**
```cpp
int startNode = graph.begin()->first;
```
- `graph.begin()` — итератор на первый (минимальный) ключ в `map`.
- `->first` — ключ пары (номер вершины). `->second` дал бы список соседей.
- Для эйлерова цикла старт может быть **любой** вершиной с ненулевой степенью — цикл всё равно пройдёт через все рёбра и вернётся в начало.

**3. `std::vector` как стек**
```cpp
std::vector<int> stack;
std::vector<int> cycle;
```
- Используется `vector`, а не `std::stack`, потому что `stack` — адаптер над `deque` и имеет overhead.
- `vector` для стека: `push_back()` = push, `pop_back()` = pop, `back()` = top — все O(1).
- Два вектора: `stack` — текущий путь (DFS-стек), `cycle` — итоговый результат (записывается при возврате).

**4. Главный цикл — ядро алгоритма Хирхольцера**
```cpp
while (!stack.empty()) {
    int v = stack.back();
```
- Цикл продолжается, пока стек не опустеет. Каждая итерация либо продвигается по ребру (push), либо фиксирует вершину в результате (pop).
- `back()` — смотрим на вершину на вершине стека, но **не удаляем** (может быть ещё непройденные рёбра).

**5. Проверка: есть ли непройденные рёбра?**
```cpp
if (edgeIndex[v] < graph[v].size()) {
    int u = graph[v][edgeIndex[v]];   // следующее непройденное ребро
    edgeIndex[v]++;                    // пометить как пройденное
    stack.push_back(u);                // перейти к соседу
```
- `graph[v].size()` — общее число рёбер из v. `edgeIndex[v]` — сколько уже пройдено.
- Если есть непройденные — берём следующее ребро, инкрементируем индекс, переходим к целевой вершине.
- `edgeIndex[v]++` — постфиксный инкремент: сначала используется старое значение (для взятия ребра), потом увеличивается.

**6. Фиксация вершины при возврате**
```cpp
cycle.push_back(v);
stack.pop_back();
```
- Если все рёбра из v пройдены — v фиксируется в `cycle` и удаляется из стека.
- Вершины записываются в **обратном** порядке обхода: подцикл записывается целиком, потом продолжается основной путь.
- Именно этот механизм автоматически «вшивает» подциклы: при разматывании стека подцикл записывается первым.

**7. Разворот результата**
```cpp
std::reverse(cycle.begin(), cycle.end());
```
- `std::reverse` из `<algorithm>` — переворачивает вектор in-place за O(n).
- Необходим, потому что вершины добавлялись при «разматывании» стека — в обратном порядке обхода.
- Без `reverse` для примера получилось бы `6→2→3→0→1→2→4→5→6→9→7→8→6`, а нужно `6→8→7→9→6→5→4→2→1→0→3→2→6`.

## Анализ сложности

### Время: O(|E|)

**Обоснование.** Каждое ребро обрабатывается **ровно один раз**: когда `edgeIndex[v]` продвигается через это ребро. Никакое ребро не проходится дважды и не пропускается. Дополнительные операции (`reverse`, инициализация `edgeIndex`) тоже не превышают O(|E|).

**Узкое место в коде:**
```cpp
while (!stack.empty()) {                          // суммарно O(|E|) итераций
    int v = stack.back();                          // O(1)
    if (edgeIndex[v] < graph[v].size()) {
        int u = graph[v][edgeIndex[v]];            // O(1) — доступ по индексу
        edgeIndex[v]++;                            // O(1) — «удаление» ребра
        stack.push_back(u);                        // O(1) амортизированно
    } else {
        cycle.push_back(v);                        // O(1) амортизированно
        stack.pop_back();                          // O(1)
    }
}
```
Все операции внутри цикла — O(1). Цикл выполняется ровно |E| + |V| раз: |E| раз для продвижения по ребру и |V| раз для фиксации вершины (каждая вершина снимается со стека ровно столько раз, сколько раз была на него положена, что суммарно = |E| + 1).

Это **колоссальный** контраст с гамильтоновым путём в overlap-графе: O(|E|) vs O(|V|² · 2^|V|). Для генома *E. coli* с ~10⁷ рёбер: ~10⁷ операций (миллисекунды) vs. ~10^(3·10⁶) операций (невычислимо).

### Память: O(|V| + |E|)

**Обоснование.** Алгоритм использует три структуры:

**Основные структуры данных:**
```cpp
std::map<int, std::vector<int>>& graph;   // O(|V| + |E|) — входной граф
std::map<int, size_t> edgeIndex;           // O(|V|) — по одному индексу на вершину
std::vector<int> stack;                    // O(|E|) в худшем случае (длинный путь без ветвлений)
std::vector<int> cycle;                    // O(|E| + 1) — результат (|E| + 1 вершин)
```
- `stack` в худшем случае содержит все |E| вершин (если граф — одна длинная цепочка без ветвлений).
- `cycle` содержит |E| + 1 элементов (каждое ребро = одна вершина + стартовая вершина).
- `edgeIndex` — |V| записей по ~16 байт (пара int + size_t).
- Итого: O(|V| + |E|).
