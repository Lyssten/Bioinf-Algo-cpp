# Overlap Graph (BA3C)

## Задача

Построить граф перекрытий для коллекции k-меров.

**Вход:** коллекция k-меров `Patterns` (по одному на строку)
**Выход:** список смежности графа перекрытий (отсортированный по исходной вершине)

Ребро ведёт от k-мера A к k-меру B, если **суффикс** A (последние k−1 символов) совпадает с **префиксом** B (первые k−1 символов). Допускаются петли (ребро из вершины в себя).

Формат входного файла Rosalind:
```text
ATGCG
GCATG
CATGC
AGGCA
GGCAT
```

**Пример:**
```
Вход: ATGCG  GCATG  CATGC  AGGCA  GGCAT
Вывод:
AGGCA -> GGCAT
CATGC -> ATGCG
GCATG -> CATGC
GGCAT -> GCATG
```

## Теория

### Граф перекрытий

Граф перекрытий (overlap graph) — **ориентированный граф**, в котором:
- **Вершины** — k-меры из входной коллекции
- **Рёбра** — направленное ребро A → B существует, если суффикс A совпадает с префиксом B

```
Suffix(A) = A[1..k-1]     (строка A без первого символа)
Prefix(B) = B[0..k-2]     (строка B без последнего символа)

Ребро A → B  ⟺  Suffix(A) = Prefix(B)
```

Пример для {ATGCG, GCATG, CATGC, AGGCA, GGCAT}:
```
CATGC:  суффикс = ATGC  →  совпадает с префиксом ATGCG  →  CATGC → ATGCG
GCATG:  суффикс = CATG  →  совпадает с префиксом CATGC  →  GCATG → CATGC
GGCAT:  суффикс = GCAT  →  совпадает с префиксом GCATG  →  GGCAT → GCATG
AGGCA:  суффикс = GGCA  →  совпадает с префиксом GGCAT  →  AGGCA → GGCAT
```

Петли допускаются: если суффикс k-мера совпадает с его же префиксом (например, для `AAAA`: суффикс = `AAA` = префикс).

### Связь с гамильтоновым путём

В графе перекрытий **реконструкция генома = нахождение пути, проходящего через каждую вершину ровно один раз** — это **гамильтонов путь**. Проблема: задача о гамильтоновом пути — **NP-полная**. Для n вершин не существует алгоритма быстрее O(n² · 2ⁿ) (алгоритм Хелда—Карпа). Уже при n = 30 вершинах перебор ~10⁹ состояний, а реальные геномы дают миллионы вершин.

Именно поэтому на практике перешли от графа перекрытий к графу де Брёйна (BA3D–BA3E), где задача сводится к **эйлерову пути** — он находится за линейное время O(|E|).

## Применение

### В биологии

- **Стратегия Overlap-Layout-Consensus (OLC).** Ранние ассемблеры (Celera Assembler, 2000 г.) использовали именно граф перекрытий для сборки генома. Celera собрал первую версию генома *Drosophila melanogaster* (120 Мб) из 3.2 миллиона ридов по 550 нуклеотидов. Этапы: (1) Overlap — найти попарные перекрытия между ридами, (2) Layout — приблизительно решить задачу гамильтонова пути, (3) Consensus — из пути вывести финальную последовательность.

- **Сборка длинных чтений.** Современные ассемблеры для PacBio и Oxford Nanopore по-прежнему используют OLC: **Canu** (2017), **Flye** (2019), **hifiasm** (2021). Причина: длинные риды (10–100 Кб) относительно немногочисленны (~500 000 для бактерии vs. ~300 миллионов коротких ридов Illumina), поэтому квадратичная сложность построения графа перекрытий терпима.

- **Палеогеномика.** Фрагменты ДНК из древних останков (неандертальцы, мамонты) очень короткие (30–60 нуклеотидов) и повреждённые. Программа **EAGER** строит граф перекрытий для таких фрагментов, что помогает восстанавливать древние геномы. Группа Сванте Паабо использовала подобный подход для секвенирования генома Денисовского человека из одной фаланги пальца.

### В других областях

- **Задача кратчайшей суперстроки (Shortest Superstring Problem).** Дан набор строк; найти кратчайшую строку, содержащую все входные как подстроки. Это NP-трудная задача, и граф перекрытий — стандартный инструмент для жадного приближения. Практическое применение — **сжатие данных**: если набор строк имеет большие перекрытия, суперстрока значительно короче конкатенации. Архиватор `xz` использует похожую идею для поиска повторяющихся подстрок.

- **Реконструкция порезанных документов.** Криминалисты и разведка восстанавливают документы, пропущенные через шредер. Каждая полоска — вершина, перекрытие текста на краях — ребро. Задача восстановления = приблизительный гамильтонов путь. DARPA в 2011 году проводила конкурс **Shredder Challenge**: команды соревновались в автоматическом восстановлении 5 порезанных документов.

- **Cборка DNA-of-Things (DoT).** Исследователи из ETH Zürich (2020) закодировали 3D-модель в синтетическую ДНК, встроили её в пластик и напечатали объект. Для декодирования фрагменты ДНК секвенировали, строили граф перекрытий и восстанавливали исходное сообщение — тот же OLC-пайплайн.

## Алгоритм

### Идея

Наивный подход: для каждой пары k-меров (A, B) проверить, совпадает ли суффикс A с префиксом B. Это O(n²) пар, каждая проверка — O(k). Для учебной задачи с десятками k-меров это приемлемо.

В реальных ассемблерах используют индексирование: хэш-таблица суффиксов позволяет найти все совпадающие пары за O(n·k) вместо O(n²·k). Но для понимания концепции графа перекрытий наивный подход — лучший: код точно повторяет определение.

### Псевдокод
```
OverlapGraph(Patterns):
    adjacency ← пустой словарь (отсортированный)
    k ← длина первого k-мера
    for each kmer_a in Patterns:
        suffix ← kmer_a[1..k-1]
        for each kmer_b in Patterns:
            prefix ← kmer_b[0..k-2]
            if suffix == prefix:
                adjacency[kmer_a].append(kmer_b)
    return adjacency
```

## Реализация на C++

```cpp
std::map<std::string, std::vector<std::string>> solve(const std::vector<std::string>& kmers) {
    std::map<std::string, std::vector<std::string>> adjacency;  // (1)

    if (kmers.empty())
        return adjacency;

    size_t k = kmers[0].size();

    for (const auto& a : kmers) {                               // (2)
        std::string suffix = a.substr(1);
        for (const auto& b : kmers) {                           // (3)
            std::string prefix = b.substr(0, k - 1);
            if (suffix == prefix) {
                adjacency[a].push_back(b);                      // (4)
            }
        }
    }

    return adjacency;
}
```

## Разбор кода

**1. `std::map` — отсортированный словарь (список смежности)**
```cpp
std::map<std::string, std::vector<std::string>> adjacency;
```
- `std::map` реализован как красно-чёрное дерево (self-balancing BST). Ключи хранятся в отсортированном порядке.
- Выбор `map` вместо `unordered_map` — для автоматической сортировки при итерации. Rosalind ожидает вывод, отсортированный по имени вершины.
- Стоимость: вставка и поиск — O(k·log n), где k — длина ключа (стоимость одного сравнения строк), n — число узлов. Для `unordered_map` было бы O(k) амортизированно, но порядок не гарантирован.
- `adjacency[a]` при первом обращении автоматически создаёт пустой `vector<string>` (value-initialization) — не нужно проверять, существует ли ключ.

**2. Внешний цикл — перебор всех вершин**
```cpp
for (const auto& a : kmers) {
    std::string suffix = a.substr(1);
```
- `const auto&` — ссылка на `const std::string`. Без `&` на каждой итерации создавалась бы копия строки.
- `substr(1)` без второго аргумента — подстрока с позиции 1 до конца. Для k-мера длины k получаем суффикс длины k−1.
- Суффикс вычисляется один раз для каждого `a` и используется во всех сравнениях с `b` — оптимизация, уменьшающая число аллокаций.

**3. Внутренний цикл — проверка всех потенциальных соседей**
```cpp
for (const auto& b : kmers) {
    std::string prefix = b.substr(0, k - 1);
    if (suffix == prefix) {
```
- Вложенный цикл проверяет **каждую** пару (a, b), включая a = b (петли разрешены).
- `prefix` создаётся заново на каждой итерации внутреннего цикла. Можно оптимизировать: предвычислить все префиксы в хэш-таблицу. Но для учебной задачи читаемость важнее.
- `suffix == prefix` — посимвольное сравнение строк длины k−1. Возвращает `false` при первом несовпадении (short-circuit).

**4. Structured bindings в форматировании вывода**
```cpp
for (const auto& [node, targets] : adjacency) {
```
- C++17 structured bindings: `[node, targets]` распаковывает `std::pair<const std::string, std::vector<std::string>>`.
- `node` — ключ (имя вершины), `targets` — список смежности.
- Итерация по `map` гарантирует лексикографический порядок ключей — вывод автоматически отсортирован.

## Анализ сложности

### Время: O(n² · k)

**Обоснование.** Для каждой из n вершин (внешний цикл) проверяем все n возможных соседей (внутренний цикл). Каждая проверка — сравнение строк длины k−1, то есть O(k).

**Узкое место в коде:**
```cpp
for (const auto& a : kmers) {                    // n итераций
    std::string suffix = a.substr(1);             //   O(k)
    for (const auto& b : kmers) {                 //   × n итераций
        std::string prefix = b.substr(0, k - 1);  //     O(k) — аллокация + копия
        if (suffix == prefix) { ... }              //     O(k) — сравнение
    }
}
```
Итого: n × (k + n × (k + k)) = O(n² · k). Вложенный цикл — главный bottleneck. При n = 10 000 и k = 20: ~10⁸ × 20 = 2 × 10⁹ операций — уже медленно (секунды). Для реальных геномов (n ~ 10⁶) квадратичный подход неприменим — именно поэтому в BA3D переходят к графу де Брёйна с линейным построением.

### Память: O(n² + n · k)

**Обоснование.**

**Основные структуры данных:**
```cpp
std::map<std::string, std::vector<std::string>> adjacency;
```
- Входные данные: n строк по k символов = O(n · k).
- Граф: в худшем случае каждая вершина связана с каждой → n² рёбер, каждое ребро — строка длины k → O(n² · k). На практике рёбер значительно меньше.
- `map` — дополнительно O(n) на узлы красно-чёрного дерева (по ~40 байт на узел).
