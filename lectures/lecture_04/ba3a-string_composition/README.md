# String Composition (BA3A)

## Задача

Найти все k-меры строки Text, отсортированные лексикографически.

**Вход:** целое число `k` и строка `Text`
**Выход:** все k-меры строки `Text` в лексикографическом порядке

Формат входного файла Rosalind:
```text
k
Text
```

**Пример:**
```
k: 5
Text: CAATCCAAC
Вывод:
AATCC
ATCCA
CAATC
CCAAC
TCCAA
```

## Теория

### k-мерная композиция строки

**k-мерная композиция** (Composition_k) строки Text — это коллекция всех подстрок длины k, извлечённых скользящим окном и отсортированных лексикографически:

```
Composition_k(Text) = sort({Text[i..i+k-1] : 0 ≤ i ≤ |Text| - k})
```

### Скользящее окно

Представьте рамку шириной k символов, которая скользит по строке слева направо, сдвигаясь на один символ за шаг. На каждом шаге рамка «вырезает» одну подстроку (k-мер). Из строки длины n получается ровно (n − k + 1) таких подстрок.

Пример для `CAATCCAAC`, k = 5:
```
CAATCCAAC     →  CAATC   (позиция 0)
 CAATCCAAC    →  AATCC   (позиция 1)
  CAATCCAAC   →  ATCCA   (позиция 2)
   CAATCCAAC  →  TCCAA   (позиция 3)
    CAATCCAAC →  CCAAC   (позиция 4)
```

Важно: k-мерная композиция — это **мультимножество** (multiset), т.е. одинаковые k-меры могут встречаться несколько раз. После сортировки порядок появления в строке теряется — именно это моделирует реальную ситуацию, когда мы получаем фрагменты, но не знаем, откуда в геноме каждый из них.

## Применение

### В биологии

- **Секвенирование нового поколения (NGS).** Секвенаторы Illumina (NovaSeq 6000, NextSeq) не могут прочитать геном целиком — они разбивают ДНК на миллионы коротких фрагментов (**ридов**) длиной 100–300 нуклеотидов. Для генома *E. coli* длиной 4.6 Мб при k = 150 получается ≈4.6 миллиона перекрывающихся 150-меров. Результат секвенирования — это, по сути, k-мерная композиция генома.

- **Подсчёт k-меров как первый шаг анализа.** Программа **Jellyfish** подсчитывает частоты k-меров в прочитанных ридах. По гистограмме частот можно оценить размер генома, уровень гетерозиготности и степень загрязнения образца — и всё это *до начала сборки*. Например, для генома человека (3.2 Гб) при k = 21 Jellyfish обрабатывает ~30× покрытие (~100 Гб ридов) за 10–15 минут.

- **Метагеномика.** Программа **Kraken2** классифицирует метагеномные риды (смесь ДНК сотен организмов) по их k-мерному составу. Каждый k-мер сравнивается с базой данных из ~15 000 геномов. Это позволяет за минуты определить видовой состав образца почвы, воды или микробиома кишечника.

### В других областях

- **Детекция плагиата.** Система Turnitin разбивает студенческие работы на n-граммы слов (аналог k-меров для текста), затем сравнивает мультимножества n-грамм между документами. Совпадение >30% n-грамм — сигнал о копировании.

- **Детекция вредоносного ПО.** Антивирусные движки (ClamAV) анализируют бинарные файлы как последовательности байтов и извлекают n-граммы. Каждая вредоносная программа имеет характерный «профиль» n-грамм, как геном — характерный k-мерный состав.

- **Обработка естественного языка (NLP).** Символьные n-граммы используются для определения языка текста: для 3-грамм " th" и "the" характерны для английского, " де" и "ого" — для русского. Google Translate использует подобный подход в подсистеме определения языка.

## Алгоритм

### Идея

Алгоритм тривиален: проходим скользящим окном по строке, на каждом шаге вырезаем подстроку длины k и добавляем в список. В конце сортируем список. Никакой хитрости — задача учит работать с базовой операцией (извлечение k-меров), которая понадобится во всех следующих задачах.

### Псевдокод
```
StringComposition(k, Text):
    kmers ← пустой список
    for i ← 0 to |Text| - k:
        добавить Text[i..i+k-1] в kmers
    sort(kmers)
    return kmers
```

## Реализация на C++

```cpp
std::vector<std::string> solve(const InputData& input) {
    std::vector<std::string> kmers;                                    // (1)

    for (size_t i = 0; i + input.k <= input.text.size(); ++i) {       // (2)
        kmers.push_back(input.text.substr(i, input.k));                // (3)
    }

    std::sort(kmers.begin(), kmers.end());                             // (4)
    return kmers;                                                       // (5)
}
```

## Разбор кода

**1. `std::vector<std::string>` — динамический массив строк**
```cpp
std::vector<std::string> kmers;
```
- `vector` хранит элементы последовательно в куче (heap). Каждый элемент — `std::string`, который сам хранит символы в отдельном участке кучи.
- Вектор без аргументов создаётся пустым: `size() == 0`, `capacity() == 0`.
- Можно зарезервировать память заранее: `kmers.reserve(n - k + 1)` — избежит переаллокаций при `push_back`. В данной задаче это необязательно, но на больших геномах ускорит в 1.5–2 раза.

**2. `i + input.k <= input.text.size()` — безопасное условие цикла**
```cpp
for (size_t i = 0; i + input.k <= input.text.size(); ++i) {
```
- Все значения имеют тип `size_t` (беззнаковый, обычно `unsigned long`).
- Условие `i + k <= size` эквивалентно `i <= size - k`, но безопаснее: если `size < k`, то `size - k` переполнит `size_t` (станет числом ~2^64), а `i + k <= size` корректно вернёт `false` без итераций.
- Это типичная ловушка C++: `size_t` не может быть отрицательным, поэтому вычитание из меньшего числа — UB-подобное поведение.

**3. `substr` + `push_back` — извлечение и сохранение k-мера**
```cpp
kmers.push_back(input.text.substr(i, input.k));
```
- `std::string::substr(pos, count)` возвращает новую строку длины `count` с позиции `pos`. Каждый вызов — аллокация в куче для строк длиннее ~15 символов (SSO-буфер).
- `push_back` получает временную строку (prvalue) → срабатывает move-конструктор: внутренний буфер строки *перемещается* в вектор без копирования символов. Стоимость — O(1) по данным, O(k) по `substr`.
- Если вектору не хватает `capacity`, он удваивает буфер и перемещает все элементы. Амортизированная стоимость `push_back` — O(1).

**4. `std::sort` — лексикографическая сортировка**
```cpp
std::sort(kmers.begin(), kmers.end());
```
- `std::sort` из `<algorithm>` — гибридный алгоритм (introsort = quicksort + heapsort + insertion sort). Гарантия O(m·log m) сравнений в худшем случае (C++11).
- Для `std::string` используется `operator<` — посимвольное лексикографическое сравнение. Одно сравнение двух строк длины k — O(k).
- `begin()` / `end()` возвращают итераторы произвольного доступа (random access iterators) — необходимое требование `std::sort`.

**5. Возврат вектора — гарантированный move**
```cpp
return kmers;
```
- В C++17 компилятор обязан применить copy elision (NRVO): объект `kmers` конструируется прямо на месте вызывающей стороны. Вектор **не копируется и не перемещается**.
- Даже без NRVO сработал бы move-конструктор: переносится только указатель на данные (3 слова), а не сами строки.

## Анализ сложности

### Время: O(m · k · log m), где m = n − k + 1

**Обоснование.** Алгоритм состоит из двух фаз:
1. Извлечение m k-меров — каждый `substr` за O(k), итого O(m·k).
2. Сортировка m строк — O(m·log m) сравнений, каждое за O(k).

Сортировка доминирует: **O(m · k · log m)**.

**Узкое место в коде:**
```cpp
std::sort(kmers.begin(), kmers.end());  // O(m·k·log m)
```
Именно эта строка определяет общую сложность. Сравнение двух строк `operator<` проходит по символам до первого различия — в худшем случае (все k-меры имеют длинный общий префикс) это O(k) на сравнение.

### Память: O(m · k)

**Обоснование.** Хранение m строк длины k в векторе.

**Основные структуры данных:**
```cpp
std::vector<std::string> kmers;  // m строк по k символов ≈ m·k байт
```
Каждая строка — отдельная аллокация в куче (если k > 15, иначе SSO). Для генома *E. coli* (n = 4.6 Мб, k = 21): m ≈ 4.6M, память ≈ 4.6M × 21 ≈ 97 Мб — ощутимо, но умещается в RAM.
