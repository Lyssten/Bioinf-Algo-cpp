# Middle Edge in Linear Space (BA5K)

## Задача

Найти **среднее ребро** в графе выравнивания двух аминокислотных последовательностей — это первый строительный блок алгоритма Хиршберга (BA5L), который выполняет глобальное выравнивание при O(n+m) памяти.

**Вход:** два пептида
**Выход:** одно ребро в формате `(r1, c1) (r2, c2)`, где (r1,c1) и (r2,c2) — узлы DP-матрицы

Формат входного файла Rosalind:
```
PLEASANTLY
MEANLY
```

**Пример:**
```
Вход:               Вывод:
PLEASANTLY          (6, 3) (7, 4)
MEANLY
```

Используется матрица BLOSUM62, штраф за гэп sigma=5.

Ребро `(6,3)→(7,4)` означает: в матрице выравнивания на строке 6, столбце 3 есть диагональный переход к строке 7, столбцу 4 — символ v[6]='N' выравнивается с w[3]='N'.

## Обозначения

| Имя | Что это |
|-----|---------|
| `v` | первая входная строка; строки DP-матрицы (0..n) |
| `w` | вторая входная строка; столбцы DP-матрицы (0..m) |
| `n` | длина v |
| `m` | длина w |
| `sigma` | штраф за гэп (= 5) |
| `mid` | средний столбец = `m / 2`; по нему разбиваем матрицу на две половины |
| `fromSrc[i]` | лучший счёт пути от (0, 0) до (i, mid) — «от источника» |
| `toSink[i]` | лучший счёт пути от (i, mid+1) до (n, m) — «к стоку» |
| `vRev` | строка v в обратном порядке; нужна для вычисления toSink |
| `wSufRev` | обращение суффикса w, начинающегося с позиции mid+1 |
| `revCol` | результат обратного DP на vRev и wSufRev; `revCol[k]` = toSink[n-k] |
| `prev`, `curr` | два рабочих вектора (столбца) в `alignColumn`; хранят текущий и предыдущий столбец DP |
| `bestI` | строка оптимального среднего ребра |
| `bestDiag` | тип ребра: `true` = диагональное (v[bestI] выровнен с w[mid]), `false` = горизонтальное (гэп в v) |
| `NEG_INF` | «минус бесконечность»; начальное значение `bestScore` |
| `(r1, c1) → (r2, c2)` | ребро в DP-матрице: от узла (строка r1, столбец c1) к (r2, c2) |
| **DP-матрица** | таблица динамического программирования размером (n+1)×(m+1); узел (i, j) означает «обработано i символов v и j символов w» |
| **backtrack** | восстановление пути в DP-матрице от конечного узла к начальному; в BA5K не используется — задача только найти ребро, а не полное выравнивание |

## Теория

### Зачем нужно среднее ребро

Стандартный алгоритм глобального выравнивания хранит матрицу DP размером n×m. Для белков длиной 10 000 а.к. это 10 000 × 10 000 × 4 байта = **400 МБ** только для DP. Плюс такая же матрица для backtrack. На практике это неприемлемо.

Алгоритм Хиршберга (1975) выполняет выравнивание за **O(n+m) памяти** — то есть для тех же 10 000 а.к. нужно всего ~80 КБ. Ключевой шаг: найти одно «среднее ребро», которое гарантированно входит в оптимальное выравнивание. Затем рекурсивно решить два независимых подпрямоугольника.

### Что такое среднее ребро

Возьмём матрицу DP размером (n+1) × (m+1). Разделим её по **среднему столбцу**: `mid = m / 2`.

Любой оптимальный путь из (0,0) в (n,m) обязан пересечь этот столбец. Значит, существует ребро, идущее из столбца `mid` в столбец `mid+1`. Таких рёбер два типа:
- **Диагональное**: из (i, mid) в (i+1, mid+1) — символы v[i] и w[mid] совпадают/заменяются
- **Горизонтальное**: из (i, mid) в (i, mid+1) — символ w[mid] выровнен против `-` в v

### Как найти это ребро за O(n+m) памяти

Трюк: вычислить только те значения DP, которые нужны для поиска ребра.

**`fromSrc[i]`** = лучший счёт пути от (0,0) до (i, mid).
Это можно посчитать, запустив стандартный глобальный DP, но останавливаясь после столбца `mid` и сохранив только последний столбец — O(n) памяти.

**`toSink[i]`** = лучший счёт пути от (i, mid+1) до (n, m).
Это можно посчитать, запустив DP **в обратном направлении** — на перевёрнутых строках v и w. Тот же O(n) памяти.

Для каждого i перебираем оба типа рёбер через столбец mid:
```
для диагонального ребра (i, mid) → (i+1, mid+1):
    total = fromSrc[i] + BLOSUM62(v[i], w[mid]) + toSink[i+1]

для горизонтального ребра (i, mid) → (i, mid+1):
    total = fromSrc[i] - sigma + toSink[i]
```

Ребро с максимальным `total` и есть среднее ребро оптимального выравнивания.

### Почему обращение строк работает

Лучший путь от (i, mid+1) до (n, m) = лучший путь от (0,0) до (n-i, m-mid-1) в матрице, построенной на **перевёрнутых** строках v и w. Это математическое свойство: счёт выравнивания не меняется при одновременном обращении обеих строк. Это позволяет использовать ту же функцию `alignColumn` в обоих направлениях.

## Применение

Среднее ребро — сердце **алгоритма Хиршберга**, встроенного в EMBOSS Needle и другие точные выравниватели для длинных последовательностей. Также родственный подход используется в Unix **diff** — сравнении текстовых файлов.

## Алгоритм

```
mid = m / 2

Прямой DP: вычислить столбец mid
  fromSrc[0..n] = alignColumn(v, w, sigma, mid)

Обратный DP: обернуть строки и вычислить последний столбец
  vRev    = reverse(v)
  wSufRev = reverse(w[mid+1..m-1])
  revCol[0..n] = alignColumn(vRev, wSufRev, sigma, len(wSufRev))
  toSink[i] = revCol[n - i]

Перебор рёбер:
  bestScore = -inf
  for i = 0..n:
    горизонтальное: total = fromSrc[i] - sigma + toSink[i]
    диагональное:   total = fromSrc[i] + BLOSUM62(v[i], w[mid]) + toSink[i+1]
    обновить best
```

## Реализация на C++

```cpp
// 1. alignColumn — вычисляет столбец targetCol DP-матрицы, используя O(n) памяти.
//    Возвращает вектор длиной n+1: prev[i] = dp[i][targetCol].
static std::vector<int> alignColumn(const std::string& v, const std::string& w,
                                    int sigma, int targetCol) {
    int n = static_cast<int>(v.size());
    // prev и curr — два соседних столбца DP.
    // prev инициализируется как dp[i][0] = -i*sigma (глобальное выравнивание).
    std::vector<int> prev(n + 1), curr(n + 1);
    for (int i = 0; i <= n; ++i) prev[i] = -i * sigma;

    for (int j = 1; j <= targetCol; ++j) {
        curr[0] = -j * sigma;   // dp[0][j] = -j*sigma (первая строка)
        for (int i = 1; i <= n; ++i) {
            int d = prev[i-1] + blosum(v[i-1], w[j-1]);
            int u = prev[i]   - sigma;
            int l = curr[i-1] - sigma;
            curr[i] = std::max({d, u, l});
        }
        // Переставляем prev и curr: prev теперь содержит столбец j.
        // std::swap — O(1), просто меняет внутренние указатели векторов.
        std::swap(prev, curr);
    }
    // После последнего swap prev содержит столбец targetCol.
    return prev;
}
```

```cpp
MiddleEdge findMiddleEdge(const std::string& v, const std::string& w, int sigma) {
    int n = static_cast<int>(v.size());
    int m = static_cast<int>(w.size());
    int mid = m / 2;   // средний столбец (целочисленное деление)

    // 2. fromSrc: прямой DP до столбца mid.
    //    fromSrc[i] = dp[i][mid] = лучший счёт от (0,0) до (i, mid).
    std::vector<int> fromSrc = alignColumn(v, w, sigma, mid);

    // 3. vRev: строка v в обратном порядке.
    //    std::string(v.rbegin(), v.rend()) — конструктор строки из
    //    обратных итераторов. rbegin() указывает на последний символ.
    std::string vRev(v.rbegin(), v.rend());

    // 4. wSufRev: обратный суффикс w, начиная с позиции mid+1.
    //    w.rbegin() — указывает на w[m-1].
    //    w.rbegin() + (m - mid - 1) — продвигаемся на (m-mid-1) позиций назад,
    //    то есть охватываем w[mid+1..m-1] в обратном порядке.
    std::string wSufRev(w.rbegin(), w.rbegin() + (m - mid - 1));

    // 5. revCol: DP на обращённых строках до конца wSufRev.
    //    revCol[k] = лучший счёт выравнивания vRev[0..k-1] с wSufRev.
    //    Перевод в исходные координаты:
    //    revCol[k] = toSink[n-k] = лучший путь от (n-k, mid+1) до (n, m).
    std::vector<int> revCol = alignColumn(vRev, wSufRev, sigma,
                                          static_cast<int>(wSufRev.size()));

    // 6. toSink — лямбда-функция для удобного доступа к toSink[i].
    //    Вместо отдельного вектора просто пересчитываем индекс: toSink[i] = revCol[n-i].
    //    [&] захватывает revCol и n по ссылке из внешней области видимости.
    auto toSink = [&](int i) -> int { return revCol[n - i]; };

    // 7. Перебор всех возможных рёбер через середину.
    //    bestScore стартует с NEG_INF (меньше любого возможного счёта).
    //    bestI — строка оптимального ребра. bestDiag — тип ребра (true=диагональ).
    int bestScore = NEG_INF;
    int bestI = 0;
    bool bestDiag = false;

    for (int i = 0; i <= n; ++i) {
        // Горизонтальное ребро (i, mid) → (i, mid+1): гэп в v, символ w[mid].
        if (mid + 1 <= m) {
            int total = fromSrc[i] - sigma + toSink(i);
            if (total > bestScore) {
                bestScore = total; bestI = i; bestDiag = false;
            }
        }
        // Диагональное ребро (i, mid) → (i+1, mid+1): v[i] выровнен с w[mid].
        // Условие i < n: символ v[i] должен существовать (0-индекс).
        if (i < n && mid < m) {
            int total = fromSrc[i] + blosum(v[i], w[mid]) + toSink(i + 1);
            if (total > bestScore) {
                bestScore = total; bestI = i; bestDiag = true;
            }
        }
    }

    // 8. Возвращаем координаты ребра в DP-матрице (0-индексация).
    if (bestDiag)
        return {bestI, mid, bestI + 1, mid + 1};  // диагональ
    else
        return {bestI, mid, bestI,     mid + 1};  // горизонталь
}
```

## Разбор кода

**`std::swap(prev, curr)` вместо `prev = curr`.** `std::swap` для `std::vector` меняет только внутренние указатели за O(1). `prev = curr` скопировало бы все n+1 элементов за O(n). На каждой из m итераций это O(n) лишних копирований — итого лишние O(n*m).

**Зачем две строки `prev` и `curr` вместо полной матрицы?**
Каждый столбец j зависит только от столбца j-1 (`prev`) и текущего столбца j (`curr`, вычисляется снизу вверх). Столбцы j-2, j-3 и раньше больше не нужны. Поэтому достаточно двух векторов длиной n+1, а не матрицы (n+1)×(m+1).

**`wSufRev = std::string(w.rbegin(), w.rbegin() + (m-mid-1))`.** Итератор `w.rbegin()` начинается с последнего символа `w[m-1]`. Продвинувшись на `m-mid-1` позиций (обратных), мы берём символы `w[m-1], w[m-2], ..., w[mid+1]` — это и есть перевёрнутый `w[mid+1..m-1]`. Конструктор `std::string(first, last)` строит строку из диапазона итераторов.

**Лямбда `toSink`.** `[&]` означает захват по ссылке всех переменных из внешней области. Функция `toSink(i)` возвращает `revCol[n - i]`. Это синтаксический сахар — компилятор инлайнит вызов, накладных расходов нет.

**`bestDiag = false` как начальное значение.** Если все `total` одинаковы (маловероятно), вернём горизонтальное ребро. Это произвольный выбор — оба типа корректны.

## Запуск

```bash

./ba5k-middle_edge -i in.txt -o out.txt
```

## Анализ сложности

**Время: O(n * m)** — два вызова `alignColumn`, каждый проходит ~m/2 столбцов за O(n) работы на столбец. Суммарно O(n * m). Перебор рёбер — O(n). Узкое место: двойной цикл `for j... for i` внутри `alignColumn`.

**Память: O(n + m)** — ключевое достижение задачи. `alignColumn` хранит только два вектора длиной n+1. `fromSrc` и `revCol` — по n+1 элементов. Никакой полной матрицы (n+1)×(m+1).
