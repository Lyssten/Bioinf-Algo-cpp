# Linear Space Alignment — Hirschberg (BA5L)

## Задача

Найти **глобальное выравнивание** двух аминокислотных последовательностей в **линейной памяти** — алгоритм Хиршберга (1975). По счёту результат идентичен обычному глобальному выравниванию (Нидлман–Вунш), но требует O(n+m) памяти вместо O(n*m).

**Вход:** два пептида
**Выход:** максимальный счёт; две выровненные строки

Формат входного файла Rosalind:
```
PLEASANTLY
MEANLY
```

**Пример:**
```
Вход:               Вывод:
PLEASANTLY          8
MEANLY              PLEASANTLY
                    -MEA--N-LY
```

Используется матрица BLOSUM62, штраф за гэп sigma=5.

Проверка счёта по выравниванию `PLEASANTLY / -MEA--N-LY`:
- P vs `-`: -5
- L vs M: BLOSUM62(L,M) = 2
- E vs E: 5
- A vs A: 4
- S vs `-`: -5
- A vs `-`: -5
- N vs N: 6
- T vs `-`: -5
- L vs L: 4
- Y vs Y: 7
- Итого: -5+2+5+4-5-5+6-5+4+7 = **8** ✓

## Теория

### Проблема памяти в глобальном выравнивании

Стандартный алгоритм Нидлмана–Вунша требует хранить матрицу DP и матрицу backtrack — каждая размером (n+1)×(m+1). При n=m=10 000 это 800 МБ. Белок длиной 10 000 а.к. — типичный случай.

### Идея Хиршберга: разделяй и властвуй

1. Найдём среднее ребро оптимального выравнивания (это делает BA5K). Ребро пересекает средний столбец `mid = m/2`.

2. Среднее ребро делит задачу на два независимых подпрямоугольника:
   - **Левый**: выровнять v[0..r1-1] с w[0..mid-1]
   - **Правый**: выровнять v[r2..n-1] с w[mid+1..m-1]

3. Рекурсивно решаем каждый подпрямоугольник тем же методом.

4. Базовый случай: если одна из строк пуста, заполняем всё гэпами.

### Почему это O(n+m) памяти

На каждом рекурсивном вызове мы держим в памяти только:
- Две строки: подстрока v и подстрока w для текущего вызова
- Два вектора длиной O(n): `fromSrc` и `revCol` для поиска среднего ребра

Глубина рекурсии: O(log m) — каждый уровень делит m пополам. На каждом уровне суммарная длина w-подстрок = m. Суммарная длина v-подстрок = n.

**Память на каждый рекурсивный уровень: O(n+m) в сумме по всем вызовам одного уровня.** Глубина O(log m). Итого O((n+m) * log m)... но на практике стек вызовов мал, и реализация ведёт себя как O(n+m).

### Два типа рёбер

После вызова `findMiddleEdge` ребро либо:

**Диагональное** `(r1, c1) → (r1+1, c1+1)`: символ `v[r1]` выравнивается с `w[c1]`.
Рекурсия:
- Левый вызов: `hirschberg(v[0..r1-1], w[0..c1-1])`
- Добавляем: символ v[r1] в v-строку, символ w[c1] в w-строку
- Правый вызов: `hirschberg(v[r1+1..n-1], w[c1+1..m-1])`

**Горизонтальное** `(r1, c1) → (r1, c1+1)`: символ `w[c1]` выравнивается против гэпа в v.
Рекурсия:
- Левый вызов: `hirschberg(v[0..r1-1], w[0..c1-1])`
- Добавляем: `-` в v-строку, символ w[c1] в w-строку
- Правый вызов: `hirschberg(v[r1..n-1], w[c1+1..m-1])`

Вертикальные рёбра (гэп в w) возникают внутри подзадач, а не на границе среднего столбца.

## Применение

**EMBOSS Needle** с опцией линейной памяти для последовательностей >100 000 а.к. Алгоритм Хиршберга встроен в реализации glnalign, Biopython pairwise2 и другие. Родственный алгоритм используется в **Unix diff** для сравнения файлов.

## Алгоритм

```
hirschberg(v, w):
  если |v| == 0: вернуть ("-"×|w|, w)   // всё w → гэпы
  если |w| == 0: вернуть (v, "-"×|v|)   // всё v → гэпы

  e = findMiddleEdge(v, w)     // средний столбец mid = |w|/2

  если e — диагональное (r1,mid)→(r1+1,mid+1):
    (A1,B1) = hirschberg(v[0..r1-1], w[0..mid-1])
    (A2,B2) = hirschberg(v[r1+1..], w[mid+1..])
    вернуть (A1 + v[r1] + A2, B1 + w[mid] + B2)

  если e — горизонтальное (r1,mid)→(r1,mid+1):
    (A1,B1) = hirschberg(v[0..r1-1], w[0..mid-1])
    (A2,B2) = hirschberg(v[r1..],   w[mid+1..])
    вернуть (A1 + '-' + A2, B1 + w[mid] + B2)
```

## Реализация на C++

```cpp
static std::pair<std::string, std::string> hirschberg(
    const std::string& v, const std::string& w, int sigma)
{
    // 1. Базовые случаи: одна из строк пуста.
    //    std::string(m, '-') создаёт строку из m символов '-'.
    //    Это выравнивание пустой строки против w: все символы w получают гэп.
    if (v.empty()) return {std::string(w.size(), '-'), w};
    if (w.empty()) return {v, std::string(v.size(), '-')};

    // 2. Находим среднее ребро. MiddleEdge содержит поля:
    //    r1, c1 — начало ребра (строка, столбец)
    //    r2, c2 — конец ребра
    //    diagonal — true если диагональное, false если горизонтальное
    MiddleEdge e = findMiddleEdge(v, w, sigma);
    int r1 = e.r1;   // строка начала ребра

    if (e.diagonal) {
        // 3. Диагональное ребро: v[r1] выравнивается с w[e.c1].
        //    Делим задачу:
        //    vL = v[0..r1-1] — часть v до символа на ребре
        //    wL = w[0..e.c1-1] — часть w до символа на ребре
        std::string vL = v.substr(0, r1);      // первые r1 символов v
        std::string wL = w.substr(0, e.c1);    // первые c1 символов w
        //    vR = v[r1+1..n-1] — часть v после символа на ребре (e.r2 = r1+1)
        //    wR = w[e.c2..m-1] — часть w после символа на ребре (e.c2 = c1+1)
        std::string vR = v.substr(e.r2);       // v.substr(r1+1)
        std::string wR = w.substr(e.c2);       // w.substr(c1+1)

        // 4. Рекурсивно решаем левую и правую подзадачи.
        //    auto [A1, B1] — structured binding (C++17): распаковывает pair.
        auto [A1, B1] = hirschberg(vL, wL, sigma);
        auto [A2, B2] = hirschberg(vR, wR, sigma);

        // 5. Склеиваем результат: левая часть + символы ребра + правая часть.
        //    v[r1] — символ v на ребре. w[e.c1] — символ w на ребре.
        return {A1 + v[r1] + A2, B1 + w[e.c1] + B2};

    } else {
        // 6. Горизонтальное ребро: '-' в v, символ w[e.c1].
        //    vL = v[0..r1-1], вся левая часть v (r1 символов)
        //    vR = v[r1..n-1], правая часть v начинается с той же позиции r1
        //    (потому что горизонтальное ребро не «тратит» символ v)
        std::string vL = v.substr(0, r1);
        std::string wL = w.substr(0, e.c1);
        std::string vR = v.substr(r1);         // не r1+1! горизонталь
        std::string wR = w.substr(e.c2);

        auto [A1, B1] = hirschberg(vL, wL, sigma);
        auto [A2, B2] = hirschberg(vR, wR, sigma);
        return {A1 + '-' + A2, B1 + w[e.c1] + B2};
    }
}

// 7. alignScore вычисляет счёт уже готового выравнивания.
//    Hirschberg не тянет счёт через рекурсию (это усложнило бы код),
//    поэтому считаем отдельно за O(|alignment|).
static int alignScore(const std::string& aV, const std::string& aW, int sigma) {
    int score = 0;
    for (size_t i = 0; i < aV.size(); ++i) {
        if (aV[i] == '-' || aW[i] == '-') score -= sigma;
        else score += blosum(aV[i], aW[i]);
    }
    return score;
}
```

## Разбор кода

**`v.substr(0, r1)` vs `v.substr(e.r2)` для диагонального vs горизонтального.**
При диагональном ребре символ `v[r1]` «расходуется» на ребро, поэтому правая часть начинается с `v[r1+1]` = `v.substr(r1+1)` = `v.substr(e.r2)`.
При горизонтальном символ v не расходуется (ребро идёт только по w), поэтому правая часть v начинается с той же позиции `r1` = `v.substr(r1)`.

**`auto [A1, B1] = hirschberg(...)` — structured bindings (C++17).** Функция возвращает `std::pair<std::string, std::string>`. Без C++17 пришлось бы писать: `auto res = hirschberg(...); auto A1 = res.first; auto B1 = res.second;`. Structured bindings делают это в одну строку. Компилятор знает тип из возвращаемого типа функции.

**Рекурсия гарантированно завершается.** На каждом вызове `|w|` уменьшается как минимум на 1 (средний столбец делит w на две строго меньшие части: `w[0..mid-1]` длиной `mid` и `w[mid+1..]` длиной `m-mid-1`). При `|w| == 0` возвращается базовый случай.

**Почему счёт вычисляется отдельно функцией `alignScore`?**
Тянуть счёт через рекурсию было бы возможно (суммировать при склейке), но усложнило бы код. Отдельный проход за O(|выравнивание|) проще и не добавляет асимптотической сложности.

**`std::string(m, '-')` в базовом случае.** Конструктор `std::string(count, char)` создаёт строку из `count` одинаковых символов. Это компактно и эффективно.

## Запуск

```bash

./ba5l-linear_space_alignment --input rosalind_ba5l.txt   # Rosalind вход

```

## Анализ сложности

**Время: O(n * m)** — на каждом уровне рекурсии суммарная работа O(n * m) (все вызовы `findMiddleEdge` суммарно обрабатывают каждую ячейку матрицы O(1) раз). Глубина рекурсии O(log m).

**Память: O(n + m)** — главное достоинство. `findMiddleEdge` хранит O(n) данных. Стек рекурсии глубиной O(log m) с O(n+m) данными на уровень. Суммарно O((n+m) * log m), что на практике близко к O(n+m). Узкое место по времени: вызов `findMiddleEdge` внутри каждого рекурсивного `hirschberg` — он содержит двойной цикл.
