# Linear Space Alignment — Hirschberg (BA5L)

## Задача

Найти глобальное выравнивание двух аминокислотных последовательностей, используя линейную память (алгоритм Хиршберга).

**Вход:** два пептида  
**Выход:** счёт; две выровненные строки

Формат входного файла Rosalind:
```
PLEASANTLY
MEANLY
```

**Пример:**
```
Вход:
PLEASANTLY
MEANLY

Вывод:
8
PLEASANTLY
-MEA--N-LY
```

Используется BLOSUM62, штраф за гэп σ=5.

## Теория

### От среднего ребра к полному выравниванию

BA5K научил нас находить ребро оптимального выравнивания, пересекающее средний столбец матрицы. BA5L использует это как строительный блок рекурсивного алгоритма.

**Алгоритм Хиршберга (1975):**  
Пусть выравниваем v и w. Оптимальный путь в DP-матрице проходит через некоторое среднее ребро (r1, mid) → (r2, mid+1). Тогда:

```
align(v, w) = align(v[0..r1-1], w[0..mid-1])
            + middle_edge_character
            + align(v[r2..n-1], w[mid+1..m-1])
```

Рекурсия уменьшает m вдвое на каждом уровне → глубина O(log m).

### Почему это O(n+m) памяти

На каждом рекурсивном вызове мы создаём два вектора длиной O(n) (для прямого и обратного DP). Рекурсивные подзадачи работают на **подстроках**, поэтому суммарный объём памяти на одном уровне рекурсии — O(n). Глубина рекурсии O(log m). Итого: O(n·log m), хотя на практике реализации с явным стеком дают O(n+m).

### Базовые случаи

- **|v| = 0:** все символы w выровнены против гэпов → (`"-"×m`, w)
- **|w| = 0:** все символы v выровнены против гэпов → (v, `"-"×n`)

Алгоритм гарантированно завершается: каждый рекурсивный вызов уменьшает |w| как минимум на 1 (mid = |w|/2 < |w| при |w| ≥ 2).

## Применение

**EMBOSS Needle** поддерживает опцию линейной памяти для выравнивания очень длинных последовательностей. При длинах >100 000 а.к. стандартный алгоритм требовал бы гигабайты — Хиршберг решает это за несколько мегабайт.

Алгоритм также лежит в основе **diff** в POSIX-системах: Unix diff (для файлов) использует родственный подход «разделяй и властвуй».

## Алгоритм

**Идея:** разбить задачу по среднему столбцу с помощью BA5K, решить подзадачи рекурсивно, склеить результат.

**Псевдокод:**
```
hirschberg(v, w):
  if |v| == 0: return ("-"×|w|, w)
  if |w| == 0: return (v, "-"×|v|)

  edge = findMiddleEdge(v, w)   // как в BA5K

  if diagonal edge (r1,mid)→(r1+1,mid+1):
    (A1,B1) = hirschberg(v[0..r1-1], w[0..mid-1])
    (A2,B2) = hirschberg(v[r1+1..], w[mid+1..])
    return (A1 + v[r1] + A2, B1 + w[mid] + B2)

  else horizontal edge (r1,mid)→(r1,mid+1):
    (A1,B1) = hirschberg(v[0..r1-1], w[0..mid-1])
    (A2,B2) = hirschberg(v[r1..],   w[mid+1..])
    return (A1 + '-' + A2, B1 + w[mid] + B2)
```

## Реализация на C++

```cpp
static pair<string,string> hirschberg(const string& v, const string& w, int sigma) {
    // 1. Базовые случаи
    if (v.empty()) return {string(w.size(),'-'), w};
    if (w.empty()) return {v, string(v.size(),'-')};

    // 2. Найти среднее ребро (встроенная копия findMiddleEdge)
    MiddleEdge e = findMiddleEdge(v, w, sigma);

    if (e.diagonal) {
        // 3. Диагональное: разбиваем по v[r1] / w[mid]
        auto [A1,B1] = hirschberg(v.substr(0,e.r1),    w.substr(0,e.c1),  sigma);
        auto [A2,B2] = hirschberg(v.substr(e.r2),      w.substr(e.c2),    sigma);
        return {A1 + v[e.r1] + A2, B1 + w[e.c1] + B2};
    } else {
        // 4. Горизонтальное: гэп в v для w[mid]
        auto [A1,B1] = hirschberg(v.substr(0,e.r1),    w.substr(0,e.c1),  sigma);
        auto [A2,B2] = hirschberg(v.substr(e.r1),      w.substr(e.c2),    sigma);
        return {A1 + '-' + A2, B1 + w[e.c1] + B2};
    }
}
```

## Разбор кода

**Structured bindings `auto [A1,B1]`** (C++17): разбирает `pair<string,string>` напрямую. Без C++17 пришлось бы писать `auto res1 = hirschberg(...)`, `auto A1=res1.first`.

**`v.substr(0, e.r1)` и `w.substr(0, e.c1)`:** создают подстроки для левого подпрямоугольника. `substr` выполняет копирование, что здесь допустимо для корректности. Оптимизация — передавать указатели/индексы — усложнила бы код.

**Счёт вычисляется отдельно:** функция `alignScore` проходит по выравниванию и суммирует BLOSUM62 за совпадения и −σ за гэпы. Это дешевле, чем тянуть счёт через рекурсию.

**Вертикальное ребро (gap in w):** в текущей реализации `findMiddleEdge` возвращает только горизонтальные и диагональные рёбра. Вертикальные гэпы (gap in w) обрабатываются внутри рекурсивных подзадач, а не как средние рёбра.

## Анализ сложности

**Время: O(n·m)** — суммарно все уровни рекурсии обходят каждую клетку матрицы константное число раз. Глубина рекурсии O(log m), на каждом уровне суммарная работа O(n·m).  
**Память: O(n+m)** — на каждом вызове создаётся два вектора O(n). Стек вызовов O(log m), длины строк на рекурсивных вызовах уменьшаются. Узкое место: `alignColumn` внутри `findMiddleEdge` вызывается при каждом рекурсивном шаге.
