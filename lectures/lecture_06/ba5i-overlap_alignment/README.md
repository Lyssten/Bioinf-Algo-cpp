# Overlap Alignment (BA5I)

## Задача

Найти наилучшее **overlap-выравнивание** двух строк: суффикс первой строки выравнивается с префиксом второй строки.

**Вход:** две строки
**Выход:** максимальный счёт; два выровненных фрагмента с символами `-` на месте пропусков

Формат входного файла Rosalind (ДНК-строки):
```
PAWHEAE
HEAGAWGHEE
```

**Пример:**
```
Вход:       Вывод:
PAWHEAE     1
HEAGAWGHEE  HEAE
            HEAG
```

Счёт проверяем вручную по выравниванию `HEAE / HEAG` (match=+1, mismatch=-2, indel=-2):
- H vs H: +1
- E vs E: +1
- A vs A: +1
- E vs G: -2  (несовпадение)
- Итого: **1** ✓

Обратите внимание: в выводе — только перекрывающаяся часть. `PAW` (начало v) и `AWGHEE` (конец w) в вывод не попадают.

## Теория

### Что значит «overlap»

Overlap-выравнивание отвечает на вопрос: насколько конец одной строки похож на начало другой? Это принципиально другая задача, чем глобальное или локальное выравнивание:

| Тип выравнивания | Свободные концы | Ищем |
|-----------------|-----------------|------|
| Глобальное | нет | лучшее выравнивание целых строк |
| Локальное  | оба конца обеих строк | лучшие подстроки |
| Overlap    | начало v и конец w | лучший суффикс v vs префикс w |

Для overlap нас интересует конкретная ситуация:
```
строка v:  [---- не важно ----][---- совпадение ---]
строка w:                       [---- совпадение ---][---- не важно ----]
```

Начало v игнорируется бесплатно. Конец w игнорируется бесплатно. За остальное платим по тарифу match/mismatch/indel.

### Как это выражается в DP

Отличие от глобального выравнивания — только в **инициализации** и в **месте поиска ответа**:

**Инициализация первой колонки (j=0):**
```
dp[i][0] = 0  для всех i от 0 до n
```
В глобальном выравнивании было бы `dp[i][0] = -i * sigma` (штраф за i пропусков). Здесь 0 — потому что мы можем **бесплатно пропустить любой префикс v**. Это и есть «свободное начало».

**Инициализация первой строки (i=0):**
```
dp[0][j] = -j * SIGMA  для j от 1 до m
```
Здесь всё как в глобальном. Мы **обязаны начать с начала w** — пропуск символов w в самом начале не бесплатный.

**Поиск ответа:**
Вместо того чтобы брать `dp[n][m]` (правый нижний угол, как в глобальном), берём **максимум по всей последней строке** `dp[n][j]` для любого j. Это значит: мы обязаны использовать всю строку v (до конца), но можем остановиться на любом префиксе w — «свободный конец».

### Схема

```
         w[0]  w[1]  w[2]  w[3]  w[4]  ...  w[m-1]
         H     E     A     G     A     ...
dp[0]:   0    -2    -4    -6    -8        (платим за пропуски w)
dp[1]:   0     ?     ?     ?     ?        (v[0]=P)
dp[2]:   0     ?     ?     ?     ?        (v[1]=A)
dp[3]:   0     ?     ?     ?     ?        (v[2]=W)
dp[4]:   0     1     ?     ?     ?        (v[3]=H, H=H -> +1)
dp[5]:   0     ?     2     ?     ?        (v[4]=E, E=E -> +1)
dp[6]:   0     ?     ?     3     ?        (v[5]=A, A=A -> +1)
dp[7]:   0     ?     ?     ?     1   ← максимум в последней строке = 1 при j=4
         ↑ все нули: бесплатный пропуск префикса v
```

Максимум в строке dp[7][*] равен 1 при j=4. Это и есть ответ: суффикс v длиной 4 (HEAE) выровнен с префиксом w длиной 4 (HEAG).

## Применение

**minimap2** — стандартный инструмент для выравнивания длинных чтений ДНК (PacBio, Oxford Nanopore). Основа алгоритма сборки генома — именно нахождение overlap'ов между ридами: конец одного рида перекрывается с началом другого.

**Overlap-Layout-Consensus (OLC)** — классическая парадигма сборки геномов. На первом шаге (Overlap) находятся все попарные перекрытия ридов. На втором (Layout) строится граф. На третьем (Consensus) — финальная последовательность.

## Алгоритм

```
Инициализация:
  dp[0][0] = 0
  dp[i][0] = 0  для всех i  (бесплатный пропуск начала v)
  dp[0][j] = -j * SIGMA     (платный пропуск начала w)

Заполнение (как в глобальном):
  for i = 1..n:
      for j = 1..m:
          dp[i][j] = max(dp[i-1][j-1] + score(v[i],w[j]),
                         dp[i-1][j]   - SIGMA,
                         dp[i][j-1]   - SIGMA)

Поиск ответа:
  bestJ = argmax(dp[n][j])  по всем j от 0 до m

Backtrack:
  i = n, j = bestJ
  пока i > 0 и j > 0:
      ... обычный backtrack ...
  если j > 0 (дошли до начала w, но не до нуля):
      добавить '-' в v и w[j] в w для оставшихся j
  если i > 0 (дошли до начала v — это бесплатный префикс):
      НЕ добавлять в вывод
  перевернуть строки
```

## Реализация на C++

```cpp
// 1. Матрица dp размером (n+1)×(m+1).
//    По умолчанию все ячейки = 0 — это сразу задаёт dp[i][0]=0 для всех i.
std::vector<std::vector<int>> dp(n + 1, std::vector<int>(m + 1, 0));

// 2. Единственное отличие инициализации от глобального:
//    только первая строка заполняется штрафами (не первая колонка!).
//    Мы платим за j пропусков в v в начале выравнивания.
for (int j = 1; j <= m; ++j)
    dp[0][j] = -j * SIGMA;

// 3. Основной цикл — идентичен глобальному выравниванию.
//    Нет нуля в max (это не локальное выравнивание!).
for (int i = 1; i <= n; ++i) {
    for (int j = 1; j <= m; ++j) {
        int diag = dp[i-1][j-1] + score(v[i-1], w[j-1]);
        int up   = dp[i-1][j]   - SIGMA;
        int left = dp[i][j-1]   - SIGMA;
        dp[i][j] = std::max({diag, up, left});
    }
}

// 4. Поиск bestJ: перебираем ВСЮ последнюю строку dp[n][*].
//    Используем >= (не >), чтобы при одинаковых счётах выбирать
//    наибольший j. Больший j означает более длинный префикс w —
//    это даёт «чистое» выравнивание без лишних хвостовых гэпов.
int bestScore = dp[n][0];
int bestJ = 0;
for (int j = 1; j <= m; ++j) {
    if (dp[n][j] >= bestScore) {
        bestScore = dp[n][j];
        bestJ = j;
    }
}

// 5. Backtrack с позиции (n, bestJ).
//    Идём назад пока оба i > 0 и j > 0.
int i = n, j = bestJ;
while (i > 0 && j > 0) {
    if (dp[i][j] == dp[i-1][j-1] + score(v[i-1], w[j-1])) {
        alignV += v[i-1]; alignW += w[j-1]; --i; --j;
    } else if (dp[i][j] == dp[i-1][j] - SIGMA) {
        alignV += v[i-1]; alignW += '-'; --i;
    } else {
        alignV += '-'; alignW += w[j-1]; --j;
    }
}

// 6. Если j > 0 после backtrack: мы дошли до строки i=0, а j ещё не ноль.
//    Это значит, dp[0][j] = -j*SIGMA — мы шли по первой строке.
//    Добавляем пропуски в v для оставшихся символов w.
while (j > 0) { alignV += '-'; alignW += w[j-1]; --j; }

// 7. Если i > 0: оставшиеся символы v — бесплатный префикс (dp[i][0]=0).
//    Мы их в вывод НЕ добавляем. Именно в этом суть overlap:
//    начало v не входит в выравнивание.

std::reverse(alignV.begin(), alignV.end());
std::reverse(alignW.begin(), alignW.end());
```

## Разбор кода

**Зачем `>= bestScore` при поиске bestJ, а не `>`?**
При строгом `>` при нескольких j с одинаковым максимальным счётом мы выбираем наименьший j (первый найденный). Это может привести к тому, что backtrack будет заканчиваться гэпами в конце w — фактически мы выровняли v против более короткого префикса w, добавив хвостовые пропуски. Оба варианта формально правильны, но `>=` даёт «более длинное» перекрытие при равном счёте, что биологически предпочтительнее.

**Почему нет `0` в `std::max`?**
В отличие от локального выравнивания (BA5F), здесь dp[i][j] может быть отрицательным — это нормально. Мы не «перезапускаем» выравнивание в середине. Ноль был бы лишним.

**Зачем `dp[0][j] = -j * SIGMA`, а не 0?**
Если бы `dp[0][j] = 0` для всех j, то алгоритм мог бы «начать» выравнивание с любого символа w, не оплатив предшествующие символы. Это сделало бы алгоритм похожим на локальное выравнивание. А нам нужно, чтобы начало w было зафиксировано: мы **обязаны** выравниваться с началом w.

**Строки alignV и alignW строятся задом наперёд**, потому что backtrack идёт от конца к началу. `std::reverse` исправляет это в конце.

## Запуск

```bash
# Без аргументов — встроенный пример PAWHEAE/HEAGAWGHEE
./ba5i-overlap_alignment

# Файл с Rosalind
./ba5i-overlap_alignment --input rosalind_ba5i.txt

# С явным выходным файлом
./ba5i-overlap_alignment --input rosalind_ba5i.txt --output result.txt
```

## Анализ сложности

**Время: O(n * m)** — двойной цикл заполнения матрицы плюс O(m) для поиска bestJ и O(n+m) для backtrack. Узкое место — строки `for i... for j` внутри `overlapAlignment`.

**Память: O(n * m)** — матрица dp хранится целиком для backtrack. Если нужен только счёт (без самого выравнивания), достаточно двух строк O(m) — но тогда backtrack невозможен.
