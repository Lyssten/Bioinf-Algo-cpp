# BA5F: Локальное выравнивание последовательностей (Local Alignment)

### 1. Задача
Найти оптимальное локальное выравнивание двух белковых последовательностей. В отличие от глобального выравнивания, локальное ищет наиболее похожие подстроки, игнорируя сильно различающиеся префиксы и суффиксы.

**Входные данные:**
*   Две строки (аминокислотные последовательности).
*   Матрица весов замен (PAM250).
*   Штраф за индель (Gap penalty, $\sigma = 5$).

**Выходные данные:**
*   Максимальный вес выравнивания.
*   Две подстроки с вставленными дефисами, представляющие оптимальное локальное выравнивание.

**Пример:**
| Вход | Выход |
| :--- | :--- |
| `MEANLY` | `15` |
| `PENALTY` | `EANL-Y` |
| | `ENALTY` |

---

### 2. Теория
Для решения задачи используется алгоритм **Смита-Ватермана** (Smith-Waterman). Основные компоненты:
*   **Матрица PAM250:** Отражает логарифмическую вероятность замены одной аминокислоты на другую в процессе эволюции.
*   **Четыре состояния:** При заполнении каждой ячейки DP-таблицы $dp[i][j]$ выбирается максимум из 4 вариантов:
    1.  `0` — возможность начать новое локальное выравнивание из текущей точки (свободный старт).
    2.  `diag` — совпадение или замена ($dp[i-1][j-1] + score(v_i, w_j)$).
    3.  `up` — вставка пропуска в первой строке ($dp[i-1][j] - \sigma$).
    4.  `left` — вставка пропуска во второй строке ($dp[i][j-1] - \sigma$).
*   **Свободный старт:** Обнуление отрицательных значений позволяет алгоритму "забывать" плохие префиксы.

---

### 3. Применение
Локальное выравнивание критически важно для поиска консервативных доменов и мотивов в белках, которые сохраняют сходство даже при сильном различии остальных частей молекулы.
*   **BLAST:** Использует эвристики для быстрого поиска локальных выравниваний в огромных базах данных.
*   **EMBOSS water:** Стандартный инструмент для построения точного локального выравнивания по алгоритму Смита-Ватермана.

---

### 4. Алгоритм
Идея заключается в заполнении матрицы динамического программирования, где $H_{i,j}$ — максимальный вес выравнивания, заканчивающегося в позициях $i$ и $j$.

**Псевдокод:**
```text
Для всех i от 0 до n, j от 0 до m:
    H[i][0] = 0
    H[0][j] = 0

Для i от 1 до n:
    Для j от 1 до m:
        H[i][j] = max(
            0,
            H[i-1][j-1] + PAM250[v[i], w[j]],
            H[i-1][j] - sigma,
            H[i][j-1] - sigma
        )
Найти MaxValue в матрице H и начать обратный путь (backtrack) до первой ячейки с 0.
```

---

### 5. Реализация на C++
Ключевые фрагменты кода для вычисления матрицы и восстановления пути:

```cpp
// 1. Инициализация и расчет DP-таблицы
for (int i = 1; i <= n; ++i) {
    for (int j = 1; j <= m; ++j) {
        int diag = dp[i-1][j-1] + score(v[i-1], w[j-1]); // 2. Вес из PAM250
        int up   = dp[i-1][j]   - sigma;
        int left = dp[i][j-1]   - sigma;
        dp[i][j] = std::max({0, diag, up, left}); // 3. Сброс в 0 (Smith-Waterman)
        if (dp[i][j] > bestScore) {
            bestScore = dp[i][j]; // 4. Поиск глобального максимума для старта backtrack
            bestI = i; bestJ = j;
        }
    }
}

// 5. Обратный путь (Backtracking)
while (i > 0 && j > 0 && dp[i][j] != 0) { // 6. Остановка при достижении 0
    if (dp[i][j] == dp[i-1][j-1] + score(v[i-1], w[j-1])) {
        alignV += v[i-1]; alignW += w[j-1]; --i; --j;
    } else if (dp[i][j] == dp[i-1][j] - sigma) {
        alignV += v[i-1]; alignW += '-'; --i;
    } else {
        alignV += '-'; alignW += w[j-1]; --j;
    }
}
```

---

### 6. Разбор кода
*   **`struct Alignment`**: Инкапсулирует результат (счет и две строки), обеспечивая чистоту возвращаемых значений из функции.
*   **`std::vector<std::vector<int>>`**: Используется для хранения DP-таблицы размером $(n+1) \times (m+1)$.
*   **Логика Backtrack**: Начинается не из правого нижнего угла (как в глобальном выравнивании), а из ячейки `(bestI, bestJ)`, где был зафиксирован максимальный вес. Завершается, как только значение в ячейке становится равным `0`.
*   **`std::reverse`**: Так как выравнивание собирается с конца (от максимума к нулю), строки необходимо перевернуть перед выводом.

### 8. Анализ сложности
*   **Временная сложность**: $O(n \cdot m)$, где $n$ и $m$ — длины последовательностей. Вложенный цикл проходит по каждой ячейке матрицы ровно один раз, выполняя константное количество операций сравнения и сложения.
*   **Пространственная сложность**: $O(n \cdot m)$ для хранения матрицы весов `dp`. При больших длинах последовательностей (десятки тысяч символов) может потребоваться оптимизация памяти (линейное пространство Хиршберга, хотя для локального выравнивания оно применяется сложнее).
