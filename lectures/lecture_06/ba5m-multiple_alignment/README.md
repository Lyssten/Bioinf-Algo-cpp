# Multiple Sequence Alignment (BA5M)

## Задача

Найти наилучшее **множественное выравнивание трёх строк**, максимизируя число позиций, где все три символа одинаковы (не гэпы).

**Вход:** три строки
**Выход:** максимальный счёт; три выровненные строки

Формат входного файла Rosalind:
```
ATATCCG
TCCGA
ATGTACTG
```

**Пример:**
```
Вход:           Вывод:
ATATCCG         3
TCCGA           AT-ATCCG-
ATGTACTG        -T---CCGA
                ATGTACTG-
```

Счёт = число позиций, где все три непробельных символа совпадают:
- Столбец 2: T/T/T — +1
- Столбец 6: C/C/C — +1
- Столбец 8: G/G/G — +1
- Итого: **3** ✓

## Обозначения

| Имя | Что это |
|-----|---------|
| `v1`, `v2`, `v3` | три входных строки |
| `n1`, `n2`, `n3` | длины строк v1, v2, v3 |
| `dp[i][j][k]` | лучший счёт выравнивания v1[0..i-1], v2[0..j-1], v3[0..k-1] |
| `i`, `j`, `k` | текущие позиции в v1, v2, v3 при заполнении DP и backtrack |
| `back[i][j][k]` | направление перехода, которое привело в ячейку (i,j,k); закодировано битами |
| `dir` | значение из `back[i][j][k]`; биты `d1 d2 d3` показывают, какие строки «продвинулись» |
| `d1`, `d2`, `d3` | биты из `dir`: 1 — строка продвинулась (взяла символ), 0 — получила гэп `-` |
| `best` | максимальный счёт среди 7 предшественников для текущей ячейки |
| `bestDir` | направление, соответствующее `best` |
| `NEG_INF` | «минус бесконечность» = `INT_MIN/2`; начальное значение `best` |
| `tryUpdate` | лямбда-функция: проверяет предшественника и обновляет `best`/`bestDir` если лучше |
| `a1`, `a2`, `a3` | строки выравнивания для v1, v2, v3 (строятся в обратном порядке) |

## Теория

### От двух строк к трём

Для двух строк DP-матрица двумерная, рёбра — 3 типа (диагональ, вверх, влево).

Для трёх строк матрица становится **трёхмерным кубом**, а рёбра — **7 типов** (2^3 - 1 = 7: все комбинации продвижения по хотя бы одному измерению):

| Код | d1 d2 d3 | Смысл |
|-----|----------|-------|
| 7 = 111 | 1  1  1 | Все три строки продвинулись — возможное совпадение |
| 6 = 110 | 1  1  0 | v1 и v2 продвинулись, v3 получает `-` |
| 5 = 101 | 1  0  1 | v1 и v3 продвинулись, v2 получает `-` |
| 3 = 011 | 0  1  1 | v2 и v3 продвинулись, v1 получает `-` |
| 4 = 100 | 1  0  0 | Только v1 продвинулась, v2 и v3 получают `-` |
| 2 = 010 | 0  1  0 | Только v2 продвинулась |
| 1 = 001 | 0  0  1 | Только v3 продвинулась |

### Функция оценки

В этой задаче используется простая оценка без штрафа за гэпы:
- **+1** — если все три символа в позиции одинаковы (и ни один не гэп)
- **0** — во всех остальных случаях (несовпадение, любой гэп)

Это означает: DP-значения монотонно неубывают, и начальное значение dp[0][0][0] = 0 корректно.

### DP-переход

```
dp[i][j][k] = лучший счёт выравнивания v1[0..i-1], v2[0..j-1], v3[0..k-1]

dp[i][j][k] = max из 7 вариантов:
  dp[i-1][j-1][k-1] + s  (если i>0, j>0, k>0; s=1 если v1[i-1]==v2[j-1]==v3[k-1])
  dp[i-1][j-1][k]        (если i>0, j>0)
  dp[i-1][j  ][k-1]      (если i>0, k>0)
  dp[i  ][j-1][k-1]      (если j>0, k>0)
  dp[i-1][j  ][k  ]      (если i>0)
  dp[i  ][j-1][k  ]      (если j>0)
  dp[i  ][j  ][k-1]      (если k>0)
```

Инициализация: dp[0][0][0] = 0, все остальные тоже 0 (нет штрафа за гэпы).

### Backtrack

Сохраняем `back[i][j][k]` — тип ребра, которое привело в ячейку (i,j,k). Кодируем как число 1–7 (биты d1d2d3). После заполнения куба идём назад от (n1, n2, n3) по ссылкам backtrack.

## Применение

**MAFFT** и **Clustal Omega** — современные инструменты множественного выравнивания белков. Внутри используют более сложные эвристики (profile-profile alignment), но концептуально основаны на той же идее 3D-DP.

Множественное выравнивание нужно для: построения филогенетических деревьев, поиска консервативных позиций в семействах белков, дизайна ПЦР-праймеров.

## Алгоритм

```
dp[0][0][0] = 0

for i = 0..n1:
    for j = 0..n2:
        for k = 0..n3: (пропускаем i=j=k=0)
            best = -inf
            если i>0 && j>0 && k>0:
                s = 1 если v1[i-1]==v2[j-1]==v3[k-1] иначе 0
                обновить best: dp[i-1][j-1][k-1] + s, направление=7
            если i>0 && j>0:
                обновить best: dp[i-1][j-1][k], направление=6
            ... (аналогично для всех 7 вариантов)
            dp[i][j][k] = best
            back[i][j][k] = лучшее направление

Ответ: dp[n1][n2][n3]

Backtrack от (n1, n2, n3):
  пока i>0 || j>0 || k>0:
      dir = back[i][j][k]
      d1 = (dir >> 2) & 1   // бит 2 (старший): двигалась ли v1
      d2 = (dir >> 1) & 1   // бит 1: двигалась ли v2
      d3 = (dir >> 0) & 1   // бит 0: двигалась ли v3
      a1 += (d1 ? v1[i-1] : '-')
      a2 += (d2 ? v2[j-1] : '-')
      a3 += (d3 ? v3[k-1] : '-')
      i -= d1; j -= d2; k -= d3
  перевернуть a1, a2, a3
```

## Реализация на C++

```cpp
// 1. dp[i][j][k] — трёхмерный вектор.
//    dp[i][j][k] = лучший счёт при выравнивании v1[0..i-1], v2[0..j-1], v3[0..k-1].
//    Инициализируем нулями: нет штрафа за гэпы, dp[0][0][0]=0 корректно.
std::vector<std::vector<std::vector<int>>> dp(
    n1+1, std::vector<std::vector<int>>(n2+1, std::vector<int>(n3+1, 0)));

// 2. back[i][j][k] — направление, из которого пришли в (i,j,k).
//    int8_t (1 байт): хватает для значений 1..7.
//    Инициализируем 0 — «не посещено» (для (0,0,0) backtrack не нужен).
std::vector<std::vector<std::vector<int8_t>>> back(
    n1+1, std::vector<std::vector<int8_t>>(n2+1, std::vector<int8_t>(n3+1, 0)));

// 3. NEG_INF используется как начальное значение best перед перебором
//    7 вариантов. Гарантирует, что первый же валидный вариант будет принят.
const int NEG_INF = std::numeric_limits<int>::min() / 2;

for (int i = 0; i <= n1; ++i) {
    for (int j = 0; j <= n2; ++j) {
        for (int k = 0; k <= n3; ++k) {
            if (i == 0 && j == 0 && k == 0) continue; // (0,0,0) уже задан

            int best = NEG_INF;
            int8_t bestDir = 0;

            // 4. tryUpdate — лямбда-функция.
            //    Принимает: координаты предшественника (pi,pj,pk),
            //    направление dir (1..7), добавочный счёт add.
            //    Обновляет best и bestDir если val > best.
            //    [&] — захват best и bestDir по ссылке.
            auto tryUpdate = [&](int pi, int pj, int pk, int8_t dir, int add) {
                int val = dp[pi][pj][pk] + add;
                if (val > best) { best = val; bestDir = dir; }
            };

            // 5. Вариант 7=111: все три строки продвинулись.
            //    Добавляем 1 если все три символа одинаковы, иначе 0.
            if (i>0 && j>0 && k>0) {
                int s = (v1[i-1]==v2[j-1] && v2[j-1]==v3[k-1]) ? 1 : 0;
                tryUpdate(i-1, j-1, k-1, 7, s);
            }
            // 6 = 110: v1 и v2 продвинулись, v3 получает гэп
            if (i>0 && j>0)         tryUpdate(i-1, j-1, k,   6, 0);
            // 5 = 101: v1 и v3, v2 — гэп
            if (i>0 && k>0)         tryUpdate(i-1, j,   k-1, 5, 0);
            // 3 = 011: v2 и v3, v1 — гэп
            if (j>0 && k>0)         tryUpdate(i,   j-1, k-1, 3, 0);
            // 4 = 100: только v1
            if (i>0)                tryUpdate(i-1, j,   k,   4, 0);
            // 2 = 010: только v2
            if (j>0)                tryUpdate(i,   j-1, k,   2, 0);
            // 1 = 001: только v3
            if (k>0)                tryUpdate(i,   j,   k-1, 1, 0);

            dp[i][j][k] = best;
            back[i][j][k] = bestDir;
        }
    }
}

// 6. Backtrack от (n1, n2, n3).
//    Строки a1, a2, a3 заполняются в обратном порядке.
std::string a1, a2, a3;
int i = n1, j = n2, k = n3;
while (i > 0 || j > 0 || k > 0) {
    int8_t dir = back[i][j][k];
    // 7. Извлекаем биты: (dir >> 2) & 1 — бит 2 (d1), и т.д.
    //    >> — побитовый сдвиг вправо. & 1 — маскирует все биты кроме 0-го.
    int d1 = (dir >> 2) & 1;  // двигалась ли v1
    int d2 = (dir >> 1) & 1;  // двигалась ли v2
    int d3 = (dir >> 0) & 1;  // двигалась ли v3
    a1 += (d1 ? v1[i-1] : '-');
    a2 += (d2 ? v2[j-1] : '-');
    a3 += (d3 ? v3[k-1] : '-');
    i -= d1; j -= d2; k -= d3;
}
std::reverse(a1.begin(), a1.end());
std::reverse(a2.begin(), a2.end());
std::reverse(a3.begin(), a3.end());
```

## Разбор кода

**Почему направление кодируется как биты?**
Три строки могут продвигаться независимо: d1, d2, d3 — каждая принимает 0 или 1. Это ровно 3 бита. Число `dir = d1*4 + d2*2 + d3` упаковывает всё в одно целое. Обратно: `d1 = (dir>>2)&1`, `d2 = (dir>>1)&1`, `d3 = dir&1`.

Пример: dir=6 = 0b110 → d1=1, d2=1, d3=0 → v1 и v2 продвинулись, v3 — гэп.

**`int8_t` для `back[i][j][k]`.** Значения 0..7 помещаются в 1 байт. Для строк длиной 50 (типичный Rosalind): 51×51×51 × 1 байт ≈ 130 КБ. Если бы использовали `int` — 520 КБ.

**Лямбда `tryUpdate`.** Объявлена как `[&](int pi, int pj, int pk, int8_t dir, int add)`. `[&]` захватывает `best`, `bestDir`, `dp` по ссылке. Это позволяет изменять `best` и `bestDir` прямо внутри лямбды. Без лямбды пришлось бы либо дублировать проверку 7 раз, либо выносить в отдельную функцию с 8 параметрами.

**Начальное значение `best = NEG_INF`.** Поскольку нет штрафа за гэпы, все 7 добавочных значений `add` равны 0 или 1. `dp` ячейки неотрицательны. Любой валидный вариант даст `val >= 0 > NEG_INF`, поэтому первый же принятый вариант не будет «неверным».

**`i -= d1; j -= d2; k -= d3` в backtrack.** Если `d1=1`, уходим из строки i (i уменьшается). Если `d1=0`, строка v1 не двигалась — i не меняется. То же для j и k. Один цикл обрабатывает все 7 случаев.

**Тройной вложенный цикл** заполняет куб в порядке (i,j,k): каждая ячейка обращается только к уже вычисленным предшественникам — все предшественники (i-1,*,*), (i,j-1,*), (i,j,k-1) посещены раньше. Это корректный порядок.

## Запуск

```bash
./ba5m-multiple_alignment                              # sample ATATCCG/TCCGA/ATGTACTG
./ba5m-multiple_alignment --input rosalind_ba5m.txt   # Rosalind вход
./ba5m-multiple_alignment -i in.txt -o out.txt
```

## Анализ сложности

**Время: O(n1 * n2 * n3)** — тройной вложенный цикл, каждая ячейка обрабатывается за O(1) (7 фиксированных предшественников). Для строк длиной 50: 50^3 = 125 000 итераций — мгновенно. Для длин 500: 1.25×10^8 итераций — уже несколько секунд. Узкое место: тройной цикл `for i for j for k` в `multipleAlignment`.

**Память: O(n1 * n2 * n3)** — два куба `dp` (`int`, 4 байта) и `back` (`int8_t`, 1 байт). Для строк длиной 200: 200^3 × 5 байт ≈ 40 МБ. Для k строк вместо 3 задача становится NP-трудной (2^k-1 предшественников, куб k-мерный) — поэтому на практике для большого k используют эвристики (MAFFT, ClustalW).
